* Welcome

This lesson teaches a small but /real/ subset of x86-64 assembly. The page you
are reading is an org-mode document; every =#+BEGIN_SRC asm= block below is
*editable* and executable right here in your browser — nothing is sent to a
server. A custom two-pass assembler turns your text into real x86-64 machine
code (REX prefixes, ModRM/SIB bytes and all), and a small interpreter steps
through it one instruction at a time.

Try this workflow:

- Click into a code block and *edit it* — it is a full editor with syntax
  highlighting.
- Press ▶ Run to assemble *and* run the block: the disassembly panel fills
  with addresses and bytes, output streams below, and the status chip ends at

- Press ⤵ Step instead to execute *exactly one* instruction at a time and

- ⟲ Reset restores the machine to its just-assembled state; the =Reset code=
  link on a block restores the original sample.
- The right-hand panel always mirrors the *active* block — the one you last
  focused or ran.

* The machine you are driving

Your program is laid out in memory the way a static Linux binary would be:

| Region  | Address (hex)        | Notes                          |
|---------+----------------------+--------------------------------|
| =.text=  | ~0x401000~            | your instructions, read-only   |
| =.data=  | right above =.text=   | =db= / =dq= data, writable     |
| stack   | ~0x7ffffffff000~ down | =rsp= starts at the top        |

The 16 general-purpose registers =rax= … =r15= are 64 bits wide. Writing a
32-bit register such as =eax= *zero-extends* into =rax= — exactly like real
hardware. The flags row shows the six status flags the subset implements.

Output goes through the Linux =write= syscall convention:

- =rax= holds the syscall number: *1* = write, *60* = exit.
- write takes the file descriptor in =rdi= (1 = stdout), the buffer address in
  =rsi= and the length in =rdx=.
- Bytes written to stdout/stderr appear in the output console and under the
  block you ran.

* Hello, x86-64

Our first program writes a NUL-free string with =write= and then calls =exit=.
The string lives in =.data=; =msg_len equ $ - msg= computes its length the
NASM way (current data position minus the label).

#+NAME: hello
#+BEGIN_SRC asm
; hello.asm — first contact: write(1, msg, len), then exit(0)
        .text
        mov     rax, 1          ; rax = 1  → syscall write
        mov     rdi, 1          ; rdi = fd 1 (stdout)
        mov     rsi, msg        ; rsi = address of the message
        mov     rdx, msg_len    ; rdx = message length
        syscall                 ; write(1, msg, msg_len)

        mov     rax, 60         ; rax = 60 → syscall exit
        xor     rdi, rdi        ; rdi = exit status 0
        syscall                 ; exit(0)

        .data
msg:      db    "Hello, x86-64!\n"
msg_len   equ   $ - msg
#+END_SRC

#+RESULTS:
: Hello, x86-64!

** What to notice while stepping

- =mov= into =rax=, =rdi=, =rsi=, =rdx= lights up those register cells — each
  step highlights everything that changed since the previous one.
- After =syscall=, =rax= holds write's return value: the number of bytes
  written (15 here).
- =xor rdi, rdi= zeroes =rdi= in two bytes — compare its encoding with
  =mov rdi, 0= in the disassembly panel.

* Counting: sum 1..10

The classic first loop: accumulate 1 + 2 + … + 10 in =rax=, then print the
result in decimal. Printing a number means converting it to digits: we
repeatedly =idiv= by 10, push each remainder (a digit) on the stack, and write
them out most-significant first — the digits come off the stack in exactly the
right order.

#+NAME: sum-1-to-10
#+BEGIN_SRC asm
; sum.asm — add 1..10 into rax, print it as decimal, exit
        .text
        ; --- accumulate 1 + 2 + ... + 10 into rax ---
        mov     rax, 0          ; rax = sum
        mov     rbx, 1          ; rbx = i (next value to add)
sum_loop:
        add     rax, rbx        ; sum += i
        inc     rbx             ; i++
        cmp     rbx, 10         ; while i <= 10, keep looping …
        jle     sum_loop
        ; rax = 55 now

        ; --- split rax into decimal digits, stacked on the stack ---
        mov     rcx, 0          ; rcx = digit count
        mov     rdi, 10         ; divisor
split:
        mov     rdx, 0          ; dividend is rdx:rax — rdx must be 0
        idiv    rdi             ; rax = rax/10, rdx = rax mod 10
        push    rdx             ; remember this digit
        inc     rcx
        cmp     rax, 0
        jg      split           ; more digits left

        ; --- write digits, most-significant first ---
emit:
        pop     rdx             ; next digit
        add     rdx, 48         ; '0' + digit
        mov     [digit], rdx    ; store as a qword; byte 0 is the character
        mov     rax, 1          ; write(1, digit, 1)
        mov     rdi, 1
        mov     rsi, digit
        mov     rdx, 1
        syscall
        dec     rcx
        cmp     rcx, 0
        jg      emit

        mov     rax, 1          ; write(1, nl, 1) — newline
        mov     rdi, 1
        mov     rsi, nl
        mov     rdx, 1
        syscall

        mov     rax, 60         ; exit(0)
        xor     rdi, rdi
        syscall

        .data
nl:     db      10
digit:  dq      0               ; scratch qword: digit character in byte 0
#+END_SRC

#+RESULTS:
: 55

** What to notice while stepping

- Watch =zf=, =sf= and =of= flip on =cmp rbx, 10= — =jle= is taken while
  =i ≤ 10= because /signed/ =i ≤ 10= (encoded as =zf= or =sf ≠ of=).
- =idiv= leaves the quotient in =rax= and the remainder in =rdx=; watch =rsp=
  go down by 8 with every =push= and back up with every =pop= (switch the
  memory viewer to /stack/ to see the digits pile up).
- =mov [digit], rdx= writes eight bytes at =digit=; the write syscall reads
  only the first one.

* Exercises

- Change =sum_loop= to sum only the *odd* numbers 1..9 (hint: =add rbx, 2=).
- Make hello print to stderr: change =rdi= to 2 and see the output again.
- Overflow the loop: sum 1..1000 and watch how few instructions that takes.
- Break it on purpose: use =al= instead of =rax= — the assembler answers with
  a line-mapped error, =8/16-bit operands are not supported in this teaching
  subset=, because that is a deliberate subset boundary, not a bug.
