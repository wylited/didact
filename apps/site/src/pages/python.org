#+TITLE: Python, X-Rayed Live
#+SUBTITLE: Real CPython 3.14 on Pyodide with execution traces, grouped variables, type drift, and shared sessions

Every Python block runs on real CPython 3.14 compiled to [[file:wasm.org][WebAssembly]] (Pyodide, ~13 MB cached locally). Instead of single-stepping, each run instruments the block and returns a full x-ray snapshot in the right-hand panel: *Trace · executed lines* (per-line hit counts and loop summaries), *Variables · grouped* (scalars, collections with lengths, functions, classes), *Types · declared vs observed* (catching annotation drift), *Traceback* / *Locals · failing frame* on errors, and *Console · stdout + stderr*.

* Execution traces and loop-variable scope

In Python, a =for= loop does not create its own block scope: the loop variable =n= stays bound in the enclosing namespace after the loop finishes, right alongside =squares=.

* Type annotations vs runtime values

Python annotations are not enforced at runtime — dividing an =int= with =/= always produces a =float= even when the variable was declared as =int=. The *Types · declared vs observed* panel compares every annotation against =type(value)= and flags mismatches automatically.

#+CAPTION: Declared annotations vs observed runtime types checked after execution
#+BEGIN_SRC typst :results svg
#set page(margin: 12pt)
#set text(size: 9pt)
#import "@preview/fletcher:0.5.8": diagram, node, edge

#let mono(s) = text(font: "DejaVu Sans Mono", size: 8pt, s)

#context {
  let rows = (
    ([*declared*], mono[total: int = 10], false),
    ([*rebound*], mono[total = total / 2], true),
    ([*observed*], mono[int -> float (5.0)], true),
  )
  let pad-x = 16pt
  let pad-h = 6.5pt
  let pad-c = 6.5pt
  let w = calc.max(
    ..rows.map(r => calc.max(measure(r.at(0)).width, measure(r.at(1)).width)),
  ) + 2 * pad-x + 6pt
  let h0 = measure([*declared*]).height + 2 * pad-h
  let h1 = measure(mono[total: int = 10]).height + 2 * pad-c
  let hh = h0 + h1 + 0.5pt
  let y-arrow = (h1 - hh) / 2
  let gap = 32pt
  let step = w + gap
  let card(i, warn) = {
    let (r0, r1, _) = rows.at(i)
    let body = grid(columns: (w - 1.4pt,),
      block(width: 100%, inset: (x: pad-x, y: pad-h), align(center, r0)),
      line(length: w - 1.4pt, stroke: 0.5pt + luma(140)),
      block(width: 100%, inset: (x: pad-x, y: pad-c), align(center, r1)),
    )
    node((i * step, 0pt), body, shape: rect, width: w, inset: 0pt,
      stroke: 0.8pt + if warn { rgb("#B3402E") } else { rgb("#1A9988") },
      fill: if warn { rgb("#FDF3F1") } else { rgb("#F2F8F6") })
  }
  diagram(
    spacing: (1pt, 1pt),
    card(0, false), card(1, true), card(2, true),
    edge((0pt, y-arrow), (step, y-arrow), "->", stroke: 0.8pt + luma(120)),
    edge((step, y-arrow), (2 * step, y-arrow), "->", stroke: 0.9pt + rgb("#B3402E")),

* Shared sessions across blocks (=:session=)

Ordinary blocks run in an isolated namespace. Adding =:session fib-lab= shares one live CPython session across blocks on the same page, just like org-babel or a Jupyter notebook: definitions from the first block stay alive for the second.

#+NAME: session-define
#+BEGIN_SRC python :session fib-lab
def fib(n: int) -> int:
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a

cache = {k: fib(k) for k in range(1, 8)}
print("cached:", cache)
#+END_SRC

#+RESULTS:
: cached: {1: 1, 2: 1, 3: 2, 4: 3, 5: 5, 6: 8, 7: 13}

Run the block above first, then run the block below — =fib= and =cache= are already in the shared session's *Variables · grouped* panel.

#+NAME: session-use
#+BEGIN_SRC python :session fib-lab
print("fib(10) =", fib(10))
print("fib(15) =", fib(15))
print("cache size =", len(cache))
#+END_SRC

#+RESULTS:
: fib(10) = 55
: fib(15) = 610
: cache size = 7

*Try editing:* modify ~cache[10] = fib(10)~ in the second block and re-run to watch =cache= grow in place across runs. Click *Reset* to wipe the shared session cleanly.
