#+TITLE: Python in the Browser
#+SUBTITLE: Real CPython 3.14 running locally on Pyodide

Hit Run on any block and it executes on real CPython compiled to WebAssembly (Pyodide, ~13 MB fetched once and cached). Nothing leaves your browser.

Each block gets its own clean global namespace, so variables do not leak from one block to another, and re-running starts fresh. There is no single-stepping here; blocks run straight through and dump their globals (with =repr= and type) into the Variables panel on the right.

* Basic output and precedence

Standard CPython =print= and arithmetic precedence (=3 * 4= binds tighter than =+=).

#+NAME: hello
#+BEGIN_SRC python
print("Hello, Python!")
print("2 + 3 * 4 =", 2 + 3 * 4)
#+END_SRC

#+RESULTS:
: Hello, Python!
: 2 + 3 * 4 = 14

* Loops leave their variable in scope

Run this loop and look at the Variables panel afterward. You will see both =squares= and =n= (=5=), because a Python =for= loop does not create a separate block scope for its loop variable.

#+NAME: squares
#+BEGIN_SRC python
squares = []
for n in range(1, 6):
    squares.append(n * n)
print("squares:", squares)
#+END_SRC

#+RESULTS:
: squares: [1, 4, 9, 16, 25]

* Functions live in the same globals dict

Iterative Fibonacci in two rolling variables. After running, =fib= shows up in the Variables panel as a =function= object, right alongside any other global.

#+NAME: fib
#+BEGIN_SRC python
def fib(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a

print("fib(10) =", fib(10))
#+END_SRC

#+RESULTS:
: fib(10) = 55

Try dropping a closing parenthesis or adding =1 / 0= to see real CPython syntax errors and tracebacks in the console panel.
