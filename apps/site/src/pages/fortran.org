* Column-major arrays, =reshape=, and =DO= loops

Fortran stores multidimensional arrays *column by column*, and every dimension can declare its own lower bound (defaulting to =1=). For a rank-2 array with lower bounds $"lo"_1, "lo"_2$ and first-dimension length $"extent"_1$, element $(i, j)$ sits at 0-based flat offset:

$$ "addr"(i, j) = (i - "lo"_1) + (j - "lo"_2) dot.c "extent"_1 $$

Because =reshape= fills column by column, ~[(i, i=1,6)]~ lands in memory as =a(1,1)= through =a(2,3)= with the first subscript advancing fastest. List-directed =print *, a= walks that same flat order.

#+NAME: col-major-loop
#+BEGIN_SRC fortran
program p
  implicit none
  integer :: i, a(2,3)
  do i = 1, 3
    print *, i
  end do
  a = reshape([(i, i=1,6)], [2,3])
  print *, a
end program p
#+END_SRC

#+RESULTS:
: 1
: 2
: 3
: 1 2 3 4 5 6

* Array sections, ~dim=~ reductions, and =matmul=

Array sections slice without copying an entire loop into source code: fixing one subscript drops that rank, while =:= keeps the full extent. Reduction intrinsics like =sum= accept a ~dim=~ argument naming *which axis to collapse*: on a 3x4 array, ~sum(a, dim=1)~ collapses rows to return the four column sums.

#+NAME: sections-matmul
#+BEGIN_SRC fortran
program p
  implicit none
  integer :: a(3,4), i
  a = reshape([(i, i=1,12)], [3,4])
  print *, a(2,:)
  print *, sum(a, dim=1)
  print *, matmul(reshape([1.,2.,3.,4.], [2,2]), reshape([1.,0.,0.,1.], [2,2]))
  print *, dot_product([1,2,3], [1,2,3])
end program p
#+END_SRC

#+RESULTS:
: 2 5 8 11
: 6 15 24 33
: 1.0 2.0 3.0 4.0
: 14

*Try editing:* change ~dim=1~ to ~dim=2~ and re-run — collapsing across columns produces the three row sums (=22 26 30=).

* Modules, =intent=, derived types, and formatted I/O

Modules own persistent data that outlives any single call and appears in the *Modules* panel. Procedure arguments share the caller's variable by reference, with =intent(in)= enforced read-only and =intent(inout)= writing updates directly back to the caller. Derived types group named components accessed with =%=, while explicit format descriptors (=F8.4=, =I5=, =ES12.4=) control exact column widths.

#+NAME: modules-and-io
#+BEGIN_SRC fortran
module m
  implicit none
  integer :: counter = 0
contains
  subroutine bump(n)
    integer, intent(inout) :: n
    counter = counter + 1
    n = n + 1
  end subroutine bump
end module m
program p
  use m, only: counter, bump
  implicit none
  type :: particle
    real :: x = 0.0
    real :: v = 1.0
  end type particle
  type(particle) :: q
  integer :: n
  n = 41
  call bump(n)
  q = particle(2.0, 3.0)
  q%x = q%x + q%v
  print *, n, counter, q%x
  write(*, '(F8.4)') 1.0 / 3.0
  write(*, '(I5)') n
  write(*, '(ES12.4)') 1234.0
end program p
#+END_SRC

#+RESULTS:

:    42

* Shared sessions across blocks (=:session lab=)

Adding =:session lab= keeps one main-program workspace, module state, and procedure table alive across blocks on the same page. Run the first block to initialize =n= and =grid=, then run the second block to resume in that same scope.

#+NAME: session-init
#+BEGIN_SRC fortran :session lab
program p
  implicit none
  integer :: n
  real :: grid(2,2)
  n = 41
  grid = reshape([1.0, 2.0, 3.0, 4.0], [2,2])
  print *, n, sum(grid)
end program p
#+END_SRC

#+RESULTS:
: 41 10.0

#+NAME: session-step
#+BEGIN_SRC fortran :session lab
n = n + 1
grid = grid * 2.0
print *, n, sum(grid)
#+END_SRC

#+RESULTS:
: 42 20.0
