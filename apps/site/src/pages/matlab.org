#+SUBTITLE: Column-major matrices, linear indexing, backslash solving, and loop columns on a steppable interpreter

Every value in this pure-TypeScript MATLAB interpreter is a 2D matrix of IEEE 754 doubles stored *column-major* in a flat array. Click *Step* or set gutter breakpoints to inspect *Workspace*, *Matrices* (showing every element's flat 0-based memory address and raw 64-bit IEEE 754 hex bytes), *Columns* (tracking which column a =for= loop is walking), *Call stack*, and *console*.

* Column-major storage and linear indexing

In C or Python, 2D arrays are laid out row by row. In MATLAB (as in Fortran), an $R times C$ matrix is stored *column by column*, so element $(r, c)$ sits at 0-based flat offset:

$$ "addr"(r, c) = (c - 1) dot.c R + (r - 1) $$

#+CAPTION: 2x3 matrix A laid out column-major in linear memory (0-based offsets)
#+BEGIN_SRC typst :results svg
#set text(size: 9pt)
#import "@preview/cetz:0.5.2": canvas, draw

#canvas(length: 1cm, {
  import draw: *
  // 2x3 logical matrix
  content((1.5, 2.35), [*Logical 2x3 matrix A*])
  let rows = (("1", "2", "3"), ("4", "5", "6"))
  for r in range(2) {
    for c in range(3) {
      let x = c * 1.0
      let y = 1.2 - r * 0.8
      let hl = c == 0
      rect((x, y), (x + 0.9, y + 0.7),

      content((x + 0.45, y + 0.35), text(font: "DejaVu Sans Mono", weight: "bold")[#rows.at(r).at(c)])
    }
  }

  // Arrow

Step through =col-major= with *Matrices* open: =A(2)= returns =4= (down column 1) and =A(3)= returns =2= (top of column 2), matching the flat layout ~A(:)' = [1 4 2 5 3 6]~.

* Matrix math, elementwise math, and backslash solving

Bare =*= performs matrix multiplication; dotted =.*= multiplies element by element. Backslash =M \ b= solves $M x = b$ via Gaussian elimination with partial pivoting instead of explicitly inverting $M$. Here one backslash fits the quadratic $p(x) = a + b x + c x^2$ through $(1, 6)$, $(2, 14)$, and $(3, 36)$, yielding $p(x) = 12 - 13x + 7x^2$.

* Slicing, deletion, and value-semantics workspaces

Assigning =[]= to a full row or column deletes it and compacts the remaining entries in *Matrices*. Functions receive arguments *by value* and run in their own private workspace — local variables never leak back into the caller.

#+NAME: slice-and-fn
#+BEGIN_SRC matlab
function t = twice(x)
  y = x * 2;
  t = y;
end

A = [1 2 3; 4 5 6];
A(:, 2) = [];
disp(A)

v = [1 2 3];
w = twice(v);
fprintf('v = %d %d %d, w = %d %d %d\n', v(1), v(2), v(3), w(1), w(2), w(3));
#+END_SRC

#+RESULTS:
: 1  3
: 4  6
: v = 1 2 3, w = 2 4 6

*Try editing:* set a breakpoint on line 2 (~y = x * 2;~) and click *Run* — *Call stack* shows =twice='s private frame and *Workspace* shows =x= and =y= isolated from =v=. Step past ~A(:, 2) = []~ and watch =3= and =6= slide to flat offsets =+2= and =+3= in *Matrices*.

* Loops walk *columns* (watch the *Columns* panel)

One of MATLAB's classic surprises: ~for c = A~ iterates over the *columns* of =A= (=[1; 4]=, then =[2; 5]=, then =[3; 6]=), never the rows or individual scalars. Step through =loop-columns= with the *Columns* panel open to watch the current column index, shape, and column-major memory start address update on every pass.

#+NAME: loop-columns
#+BEGIN_SRC matlab
A = [1 2 3; 4 5 6];
s = 0;
for c = A
  s = s + sum(c);
end
fprintf('loop total:       %d\n', s);
fprintf('vectorized total: %d\n', sum(sum(A)));
#+END_SRC

#+RESULTS:
: loop total:       21
: vectorized total: 21

*Try editing:* replace ~for c = A~ with ~for c = A'~ (transposed!) and step through *Columns* — the loop now takes only 2 passes (columns of $A^T$ are the rows of $A$), still summing to =21=.
