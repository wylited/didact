#+TITLE: MATLAB: Everything Is a Column-Major Matrix
#+SUBTITLE: Matrix ops, linear indexing, backslash solving, workspaces, and vectorization — step by step

* What this interpreter supports

This page runs a steppable MATLAB-style teaching interpreter in TypeScript. Every value is a 2D matrix stored *column-major* in a flat array of IEEE 754 doubles — the exact memory layout real MATLAB uses.

Supported features include matrix literals, ranges, matrix vs elementwise operators (=+ - * / \ .=), indexing with =end=, =if=/=for=/=while=, top-level functions, and core builtins (=zeros=, =sum=, =sort=, =det=, =inv=). Unsupported constructs (cell arrays ={}=, structs, =@= function handles, =try/catch=, and strings as variables) fail cleanly with the line number.

Three small differences from desktop MATLAB:

- Columns print separated by two spaces, and decimals trim trailing zeros (=0.5= instead of =0.5000=).
- There is no =rand=, so every run is 100% deterministic.
- Inside =[ ]=, a minus sign always starts a new element, so write =[(1 - 2)]= when you mean subtraction.

* Matrix literals, ranges, and column-major layout

Inside =[ ... ]=, spaces or commas separate columns, and semicolons (or newlines) separate rows.

#+BEGIN_SRC matlab
A = [1 2; 3 4]
disp(A(:)')
disp(A(2))
disp(A(3))
#+END_SRC

#+RESULTS:
: A =
:
: 1  2
: 3  4
: 1  3  2  4
: 3
: 2

Look at why =A(2)= is =3= and =A(3)= is =2=: MATLAB stores =[1 2; 3 4]= *column by column* as =[1, 3, 2, 4]=. Single-step the block and check the *Matrices* panel: each row shows a stored element, its 0-based flat address (=(col - 1) * rows + row - 1=), and its 64-bit IEEE 754 hex pattern.

Ranges (=start:step:stop=) build row vectors:

#+BEGIN_SRC matlab
v = 1:0.5:3
disp(v)
w = 5:-2:1;
disp(w)
#+END_SRC

#+RESULTS:
: v =
:
:   1  1.5    2  2.5    3
:   1  1.5    2  2.5    3
: 5  3  1

Watch the *Workspace* panel for every variable's shape and preview (changed values highlight after each step), and note that a trailing semicolon suppresses printing.

* Matrix math vs elementwise math

In MATLAB, bare operators do linear algebra and dotted operators work element by element:

- =A * B= is matrix multiplication; =A .* B= multiplies matching entries.
- =/= and =\= solve linear systems; =./= and =.\= divide elementwise (broadcasting scalars).
- =^= is matrix power; =.^= is elementwise power; ='= transposes.

#+BEGIN_SRC matlab
A = [1 2; 3 4];
B = [5 6; 7 8];
disp(A * B)
disp(A .* B)
#+END_SRC

#+RESULTS:
: 19  22
: 43  50
:  5  12
: 21  32

* Solving linear systems with =\=

=M \ b= solves =Mx = b= using Gaussian elimination with partial pivoting — faster and more accurate than computing =inv(M) * b=. Below, we fit a quadratic =p(x) = a + bx + cx^2= through =(1, 6)=, =(2, 14)=, and =(3, 36)= in one line:

#+BEGIN_SRC matlab
M = [1 1 1; 1 2 4; 1 3 9];
b = [6; 14; 36];
c = M \ b;
disp(c')
#+END_SRC

#+RESULTS:
:  12  -13    7

That gives =p(x) = 12 - 13x + 7x^2=. If =M= is singular, both =M \ b= and =inv(M)= stop with a line-numbered singularity error.

* Slicing, =end=, and deleting slices

MATLAB indexing is 1-based, =:= selects an entire row or column, and =end= evaluates to the size of that dimension. Assigning =[]= to a full row or column deletes it and compacts the matrix in memory.

#+BEGIN_SRC matlab
A = [1 2 3; 4 5 6];
disp(A(1:2, 2:end))
disp(A(:, 2))
disp(A(1, :))
A(1, :) = [10 20 30];
A(:, 2) = [];
disp(A)
#+END_SRC

#+RESULTS:
: 2  3
: 5  6
: 2
: 5
: 1  2  3
: 10  30
:  4   6

Watch the *Matrices* panel when =A(:, 2) = []= runs: the surviving elements shift to new contiguous addresses. Out-of-bounds writes fail with a line-numbered error (preallocate with =zeros= instead of growing matrices dynamically).

* Functions have isolated workspaces

Every function call gets its own private workspace, and arguments are passed by value (copied). Assigning =y= inside =twice= never touches or shows up in the script's base *Workspace* panel. Set a breakpoint on line 3 to see =twice='s local variables in the *Call stack* panel. Functions can also return multiple values, like =function [q, r] = divmod(a, b)=.

#+BEGIN_SRC matlab
function t = twice(x)
  y = x * 2;
  t = y;
end
v = [1 2 3];
w = twice(v);
fprintf('v is still %d %d %d\n', v(1), v(2), v(3));
fprintf('w is      %d %d %d\n', w(1), w(2), w(3));
#+END_SRC

#+RESULTS:
: v is still 1 2 3
: w is      2 4 6

Note: =fprintf= supports literal format strings with =%d=, =%.Nf=, =%%=, and =\n=. Strings are display-only in this subset (=disp=, =fprintf=, =error=).

* Vectorization: same result, fewer steps

In MATLAB, =for c = A= iterates over the *columns* of =A= (=[1; 4]=, then =[2; 5]=, then =[3; 6]=). Both the loop and =sum(sum(A))= print =21=, but watch the step counter: the vectorized call pushes the looping into a single builtin instead of stepping through every iteration in the interpreter. (=sum(A)= sums down each column into a row; =sum(A, 2)= sums across each row into a column.)

#+BEGIN_SRC matlab
A = [1 2 3; 4 5 6];
s = 0;
for c = A
  s = s + sum(c);
end
fprintf('loop total:      %d\n', s);
fprintf('vectorized total: %d\n', sum(sum(A)));
#+END_SRC

#+RESULTS:
: loop total:      21
: vectorized total: 21
