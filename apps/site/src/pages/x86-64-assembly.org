* Registers and Linux syscalls

x86-64 provides sixteen 64-bit general-purpose registers. On Linux, syscalls follow a fixed register convention:

- =rax=: syscall number before =syscall=, and its return value afterward
- =rdi=, =rsi=, =rdx=: first three syscall arguments
- =rsp=: stack pointer (starts near the top of a 1 MiB stack)

The two syscalls used on this page:

| Syscall | =rax= | Arguments                     |
|---------+-------+-------------------------------|
| =write= | 1     | =rdi= fd, =rsi= buf, =rdx= len |
| =exit=  | 60    | =rdi= exit code               |

=write= copies =rdx= bytes from =rsi= to file descriptor =rdi= (=1= is stdout) and returns the byte count in =rax=. =exit= halts the CPU.

* Your first syscall: =write=

=section .data= puts the message string in the data segment (mapped at =0x601000=), and =msg_len equ $ - msg= calculates its length at assembly time using the current location counter =$=.

Step through the block and watch =rax=, =rsi=, and =rdx= load before =syscall=. Right after =syscall= runs, notice =rip= advances by 2 bytes and =rax= becomes =14= (the number of bytes written).

#+NAME: hello
#+BEGIN_SRC asm
; hello.asm — your first syscall
; Linux x86-64: syscall number in rax, args in rdi, rsi, rdx.

section .text
start:
    mov rax, 1            ; sys_write
    mov rdi, 1            ; fd 1 = stdout
    mov rsi, msg          ; rsi <- address of the string
    mov rdx, msg_len      ; rdx <- how many bytes to write
    syscall               ; write(1, msg, 14) -> rax = 14

    mov rax, 60           ; sys_exit
    xor rdi, rdi          ; exit code 0
    syscall               ; the machine stops here

section .data
msg:     db "Hello, world!", 10    ; 10 = '\n'
msg_len  equ $ - msg
#+END_SRC

#+RESULTS:
: Hello, world!

* Loops, flags, and ASCII conversion

Assembly has no built-in integer printer — to print =55=, you convert each digit to its ASCII byte (=5 + '0' = 0x35=) and pass the buffer to =write=.

Below, =rax= sums =1..10= while =rbx= counts up. Watch the CPU flags panel as =cmp rbx, 10= updates =ZF= and =CF=, and =jbe next= jumps back while =rbx <= 10=. Then =div rcx= divides =rdx:rax= by =10= (putting the tens digit in =rax= and ones digit in =rdx=), adds ='0'= to each, and writes them into =digits=.

#+NAME: sum-loop
#+BEGIN_SRC asm
; sum.asm — sum 1..10 and print the result
; 1 + 2 + ... + 10 = 55, which is exactly two ASCII digits.

section .text
start:
    xor rax, rax          ; sum = 0
    mov rbx, 1            ; i = 1
next:
    add rax, rbx          ; sum += i
    inc rbx               ; i++
    cmp rbx, 10           ; flags: i vs 10
    jbe next              ; loop while i <= 10 (short backward jump)

    ; split 55 into digits: 55 / 10 = 5 remainder 5
    mov rcx, 10
    xor rdx, rdx          ; rdx must be 0 before div (rdx:rax / rcx)
    div rcx               ; rax = 5 (tens), rdx = 5 (ones)
    add al, '0'           ; 5 -> ASCII '5'
    add dl, '0'
    mov [digits], al      ; store tens digit into the buffer
    mov [digits+1], dl    ; store ones digit
    mov byte [digits+2], 10   ; newline

    mov rax, 1            ; write(1, digits, 3)
    mov rdi, 1
    mov rsi, digits
    mov rdx, 3
    syscall

    mov rax, 60           ; exit(0)
    xor rdi, rdi
    syscall

section .data
digits:  db "00", 10      ; scratch buffer, overwritten at run time
#+END_SRC

#+RESULTS:
: 55

After running, check *Memory · .data* at =0x601000=: the initial bytes =30 30 0a= (="00\n"=) have been overwritten with =35 35 0a= (="55\n"=). Click *Reset* to watch them snap back.

* Supported syntax quick reference

- Intel syntax only (destination first): =mov rax, 42=
- Labels: =name:= and NASM-style =.local= labels
- Sections: =section .text= / =section .data= (or =.text= / =.data=)
- Data directives: =db=, =dw=, =dd=, =dq= with numbers, chars, and strings
- Constants & expressions: =name equ expr= (or =name = expr=), =+ - * /=, hex =0x=, binary =0b=, chars ='a'=
- Memory operands: =[digits+1]=, =byte [digits+2]=, =[rax]=, =[rsp+8]=
- Comments: =;= to end of line

Assembly errors highlight the exact line in red.
