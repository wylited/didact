#+SUBTITLE: Every MIPS archetype as a self-checking drill — the kernel is your answer key

So far this series built the machine piece by piece: the fetch–decode–execute loop on The Machine Model, the extension rules on Arithmetic and Logic, the three formats on Machine Code: R, I, J, the call discipline on Procedures and the Stack. This page adds no new material. It is the drill yard: the MIPS question archetypes from HW1 and the tutorials, each rebuilt as an exercise that checks itself.

The kernel is your answer key. Every block is fed to a real assembler and a real interpreter. The =Program= panel prints the true encoding of every word you type, the =Registers= panel is a live trace, and =Run= re-assembles whatever is in the editor — a wrong guess earns an exact, line-mapped correction instead of a lost mark.

* How this gym works

Mental model: every drill is the same three-beat loop. Predict on paper. Run. Compare with the panels.

- Predict first. Encoding drills want a field table; trace drills want 32-bit binary work; translation drills want assembly lines on paper.
- Run the block. A breakpoint stops the machine before the instruction on the clicked line; =Run= again continues a paused session. Editing the text makes the next =Run= re-assemble from scratch.
- Compare. =Registers= for values, =Program= for encodings, =.data= for memory bytes, =Output= for behavior. The register written by the last executed instruction carries the =changed= flag.

Two exam laws to rehearse here. The number-system law: HW1 Q2 prints "No points will be given if answers are in a different number system format" — encoded answers are =0x= plus eight hex digits. The steps law: HW1 Q3 and Q5(a) trade partial credit for shown work, so the field table and the binary string are worth writing even when the final word is right.

* Encode drills: assembly to hex

Mental model: encoding is a fixed function from one source line to one 32-bit word. There are three shapes. R packs =op | rs | rt | rd | shamt | funct=. I packs =op | rs | rt= plus a 16-bit immediate. J packs =op= plus a 26-bit field. The register numbers are yours to know: =$t0= through =$t7= are 8 through 15, =$s0= through =$s7= are 16 through 23. Opcode and funct values are on the reference card.

The block below carries five drill lines, marked DRILL 1 to DRILL 5. Hand-encode each to eight hex digits before running anything. Four one-word setup lines precede them, and one dead line sits between the =j= and its target, so every address is countable from the source: text starts at =0x00400000=, and word =n= lives at =0x00400000 + 4n=.

#+NAME: encode-drill
#+BEGIN_SRC mips
# encode-drill.asm — hand-encode the five DRILL lines, then check the listing
        .data
vals:   .word   11, 22, 33           # vals[2] = 33 lives at vals+8
        .text
main:   lui     $t0, 0x1001           # setup: $t0 = 0x10010000 = address of vals
        addi    $t5, $zero, 90        # setup: $t5 = 90
        addi    $s2, $zero, 40        # setup: $s2 = 40
        addi    $s3, $zero, 6         # setup: $s3 = 6
        sub     $t3, $t5, $s2         # DRILL 1 (R-type): fields op|rs|rt|rd|sh|funct
        sll     $s4, $s3, 5           # DRILL 2 (R shift): the source sits in rt
        addi    $t6, $t7, -100        # DRILL 3 (I-type): imm is 16-bit two's comp
        lw      $s5, 8($t0)           # DRILL 4 (I-type): rt is the destination
        j       checked               # DRILL 5 (J-type): field = target >> 2
        addi    $a0, $zero, 0         # dead code: the jump must clear this line
checked: add    $a0, $s5, $zero       # print what the lw loaded
        addi    $v0, $zero, 1         # syscall 1: print int
        syscall
        addi    $v0, $zero, 10        # syscall 10: exit
        syscall
#+END_SRC

#+RESULTS:
:33

After =Run=: read the bytes column of the =Program= panel for the five drill
words — they sit at =0x00400010= through =0x00400020=, since word =n= lives at
=0x00400000 + 4n= and the drills are words 4 to 8. The =Output= printing =33=
proves the mechanics — the =lw= fetched =vals[2]= and the =j= hopped the dead
line. Hover a row to see that source line's trailing comment as its tooltip.

The traps this drill rehearses. DRILL 3's immediate is negative, so the low 16 bits are the two's complement of 100: write +100, invert, add one. DRILL 2's source register goes in =rt=, with =rs= left zero. DRILL 5's field is the target address shifted right by two. Exam angle: HW1 Q2 (12 points) and Q5(a) (8 points), both hex-only, both crediting the field table as shown work.

* Decode drills: hex to assembly

Mental model: decoding runs the encoder backwards. Split the top six bits first. All zeros means R-type, and the last six bits — funct — name the operation. Anything else is an opcode, and the card names it. Then unpack the remaining fields, map numbers back to register names, and read any immediate whose bit 15 is set as a negative two's-complement value.

The block holds three drilled lines, each commented with the hex word it decodes from. Decode all three on paper first. While you are there, predict which =buf= element the load reads: its effective address is =buf + 256 − 228=.

If the three hex words look familiar, they should: they are the same three
words you decoded on Machine Code: R, I, J — now without the walkthrough.

#+NAME: decode-drill
#+BEGIN_SRC mips
# decode-drill.asm — three hex words to decode, then a round trip
        .data
buf:    .word   1, 2, 3, 4, 5, 6, 7, 4919    # buf[7] is the lw's target
        .text
main:   la      $t4, buf                     # setup: $t4 = address of buf
        addi    $t4, $t4, 256                # setup: $t4 = buf + 256
        addi    $s2, $zero, 34               # setup: $s2 = 34
        lw      $t3, -228($t4)               # decode me first: 0x8D8BFF1C
        srl     $s1, $s2, 4                  # decode me first: 0x00128902
        add     $s0, $s1, $s2                # decode me first: 0x02328020
        add     $a0, $t3, $zero              # print what the lw loaded
        addi    $v0, $zero, 1
        syscall
        addi    $a0, $zero, 10               # '\n' between the two proofs
        addi    $v0, $zero, 11
        syscall
        add     $a0, $s0, $zero              # print the add's result
        addi    $v0, $zero, 1
        syscall
        addi    $v0, $zero, 10               # exit
        syscall
#+END_SRC

#+RESULTS:
:4919
:36

Round-trip check: type your three decoded instructions over the drilled lines, keep the setup, =Run=. Two things must come back unchanged — the same three words in the =Program= panel, and the same =Output=. Decode, re-encode, compare: that is the complete A3 skill.

The traps. The =0xFF1C= low half has bit 15 set, so the offset is negative. The shift reads its source from =rt=. The =add= takes its destination from =rd= while =lw= takes its destination from =rt=.

One more panel read, for endianness. The =.data= panel shows the loaded word — 4919, which is =0x1337= — stored as =37 13 00 00=: least significant byte at the lowest address. A big-endian machine would show =00 00 13 37=. That byte order is the whole of A10, visible in one row of the hexdump.

* Trace drills: predict the registers

Mental model: a trace is you being the machine. Keep the register values on paper, execute one instruction at a time, and write out the bits for every shift and mask — the exam wants the binary shown, not only the hex. The traps worth drilling are =sra= against =srl= on a negative value, and the width of the =andi= mask.

Predict =$t2=, =$t3=, =$t4= and =$t5= at the =BREAK HERE= line. Then click that line's number in the gutter, =Run=, and compare with the =Registers= panel: the machine stops before the line executes, so all four answers are live. =$t5= wears the =changed= flag — the =andi= was the last instruction to land.

#+NAME: trace-drill
#+BEGIN_SRC mips
# trace-drill.asm — predict $t2..$t5 at the BREAK line
        .data
wipe:   .asciiz "gone - the breakpoint was your only look"
        .text
main:   lui     $t0, 0xBBBB            # $t0 = 0xBBBB0000
        ori     $t0, $t0, 0xBBBB       # $t0 = 0xBBBBBBBB, a negative value
        lui     $t1, 0x1234            # $t1 = 0x12340000
        ori     $t1, $t1, 0x589A       # $t1 = 0x1234589A
        sll     $t2, $t0, 4            # predict $t2: zeros enter at the top
        or      $t2, $t2, $t1          # predict $t2 again: a full 32-bit OR
        sra     $t3, $t0, 4            # predict $t3: does the sign bit copy down?
        srl     $t4, $t0, 4            # predict $t4: zero bits or sign bits on top?
        andi    $t5, $t2, 0xFFFF       # predict $t5: how wide is the mask?
        add     $t2, $zero, $zero      # BREAK HERE: machine stops before this line
        add     $t3, $zero, $zero      # from here on $t2..$t5 are wiped
        add     $t4, $zero, $zero
        add     $t5, $zero, $zero
        la      $a0, wipe              # print the marker
        li      $v0, 4
        syscall
        li      $v0, 10
        syscall
#+END_SRC

#+RESULTS:
:gone - the breakpoint was your only look

=Run= again to continue: the program wipes =$t2= through =$t5= and prints its marker, so the final panel state no longer holds the answers. The breakpoint was your only look — by design, because on paper you also get one pass.

Exam angle: HW1 Q3, "Answer MUST be in hexadecimal number system format or otherwise 0 pt." Its killer instance is Q3(b), =andi $t2, $t2, -1=: the immediate zero-extends, so the mask is =0x0000FFFF= and not all ones. This assembler refuses the negative spelling outright — write =andi $t2, $t2, 0xFFFF= and the lesson is the same, from the safe side.

* C to MIPS under constraints

Mental model: a constrained translation is packing a fixed suitcase. The registers are dictated, one branch instruction is allowed, pseudo-instructions are banned. The method from Branches, Loops, and C Translation carries over: map each C variable to its dictated register, compile statement by statement, and invert the condition when the allowed branch tests the wrong thing.

The fragment, HW1 Q1(a) style. Write your answer on paper before reading the
block below it. One honesty note: this fragment tweaks the operators of the
real Q1(a), so the shape — dictated registers, =bne= only, a trailing
statement outside the =if= — is the same but you cannot pattern-match the HW1
answer; you have to compile the fragment yourself.

#+NAME: translate-spec
#+BEGIN_SRC text
/* C fragment — HW1 Q1(a) style.
   Registers are dictated: i -> $t0, j -> $t1, f -> $s1, g -> $s2, h -> $s3.
   Branching: the bne instruction only.
   Instructions: the course subset, no pseudo-instructions. */
if (i == j)
    f = g - h;
f = f + i;
#+END_SRC

#+NAME: translate-drill
#+BEGIN_SRC mips
# translate-drill.asm — one reference answer for the C fragment above
main:   addi    $t0, $zero, 2          # i = 2    (edit these five inits
        addi    $t1, $zero, 2          # j = 2     to steer the other path,
        addi    $s1, $zero, 0          # f = 0     then Run again)
        addi    $s2, $zero, 20         # g = 20
        addi    $s3, $zero, 8          # h = 8
        bne     $t0, $t1, skip         # if (i != j) skip the then-part
        sub     $s1, $s2, $s3          # then: f = g - h
skip:   add     $s1, $s1, $t0          # f = f + i -- OUTSIDE the if
        add     $a0, $s1, $zero        # print f
        addi    $v0, $zero, 1
        syscall
        addi    $v0, $zero, 10
        syscall
#+END_SRC

#+RESULTS:
:14

Notes on the reference answer. =bne= branches when =i= and =j= differ, so the then-part falls through — the cheaper of the two =if= shapes, and the reason T3 asks which translation is more efficient. The last statement sits outside the =if= and runs on both paths; HW1 Q1(a) grades exactly that trap. The block stays inside the course subset — even the print and exit avoid pseudo-instructions, spelling =li $v0, 1= as =addi $v0, $zero, 1=, so every source line is exactly one machine word in the listing.

Check yourself twice. First predict the printed =f= for the shipped inits, =i= = 2 and =j= = 2, then =Run=. Then set =i= to 5 and predict again before running: the then-part is skipped and only the trailing statement executes.

* Validity critique: the canonical four

Mental model: legality is field arithmetic. Every field has a width — 16 bits of immediate, 5 bits of shift amount — and the instruction set is a closed list. HW1 Q4(a) through (d) is the canonical set, and all four rejections are executable in this kernel. Each block below ships the broken line as a comment: remove the leading =# = on the marked line, press =Run=, and the block answers with the quoted rejection on line 5. The =restore sample= link brings the shipped text back.

#+NAME: validity-1
#+BEGIN_SRC mips
# validity-1.asm — HW1 Q4(a): the addi immediate overflows 16 bits
        .text
main:   addi    $t2, $zero, 1000       # $t2 = 1000, so the fix is checkable
# remove the leading "# " on the next line, then Run, to see the rejection:
# addi    $t1, $t2, 65536      # INVALID: 65536 > 32767
        lui     $t8, 1                 # fix, part 1: $t8 = 0x00010000 = 65536
        add     $t1, $t2, $t8          # fix, part 2: $t1 = $t2 + 65536
        add     $a0, $t1, $zero        # print the proof
        addi    $v0, $zero, 1
        syscall
        addi    $v0, $zero, 10
        syscall
#+END_SRC

#+RESULTS:
:66536

The rejection: "addi immediate 65536 does not fit in 16 bits (use li to load big values)". The signed immediate spans =−32768..32767=; 65536 needs a 17th bit. The fix builds the constant first — =lui $t8, 1= makes =0x00010000= — then adds. The printed =66536= is the value the broken line was reaching for. The official solution builds the constant in =$t1= itself — =lui $t1, 0x0001=; =ori $t1, $t1, 0=; =add $t1, $t1, $t2= — keeping the original add; any free register works, and in this editor a =$t= register is safer than =$at=, because pseudo-op expansions clobber =$at= (=$at= is the scratch in the Q4(c) fix below, where every line is a real instruction).

#+NAME: validity-2
#+BEGIN_SRC mips
# validity-2.asm — HW1 Q4(b): there is no subi in MIPS
        .text
main:   addi    $t2, $zero, 100        # $t2 = 100
# remove the leading "# " on the next line, then Run, to see the rejection:
# subi    $t4, $t2, 0x39        # INVALID: subi does not exist
        addi    $t4, $t2, -57          # fix: addi with a negative immediate
        add     $a0, $t4, $zero        # print the proof
        addi    $v0, $zero, 1
        syscall
        addi    $v0, $zero, 10
        syscall
#+END_SRC

#+RESULTS:
:43

The rejection: "unknown instruction 'subi'". There is no =subi= in MIPS — immediates are 16-bit signed, so =addi= with a negative immediate already subtracts. The fix is =addi $t4, $t2, -57=; note that =0x39= is 57.

#+NAME: validity-3
#+BEGIN_SRC mips
# validity-3.asm — HW1 Q4(c): a 32-bit constant cannot ride in ori
        .text
main:
# remove the leading "# " on the next line, then Run, to see the rejection:
# ori     $t2, $t5, 0x1A2B3C4D  # INVALID: the imm field is 16 bits
        lui     $at, 0x1A2B            # fix, part 1: top half into $at
        ori     $at, $at, 0x3C4D       # fix, part 2: OR in the low half
        or      $t2, $t5, $at          # fix, part 3: the OR the question asked for
        add     $a0, $t2, $zero        # print the proof
        addi    $v0, $zero, 1
        syscall
        addi    $v0, $zero, 10
        syscall
#+END_SRC

#+RESULTS:
:439041101

The rejection: "ori immediate 439041101 must be 0..65535 (it is zero-extended, not sign-extended — use li for big values)". The constant =0x1A2B3C4D= is 32 bits wide; the field holds 16. The official Q4(c) correction is three instructions and keeps the OR the question asked for: build the constant in the scratch register — =lui $at, 0x1A2B=, then =ori $at, $at, 0x3C4D=, the right partner because zero-extension cannot disturb the top half — then =or $t2, $t5, $at=. ($t5 reads 0 here, so the print equals the constant; =$at= is safe because none of the three lines is a pseudo-op the assembler would expand.) The two-line builder alone — =lui $t2, 0x1A2B=; =ori $t2, $t2, 0x3C4D=, the constant builder from Arithmetic and Logic — is the A11 answer, "use the minimum number of instructions", not the Q4(c) fix: it loads the constant into =$t2= but never performs the OR with =$t5=.

#+NAME: validity-4
#+BEGIN_SRC mips
# validity-4.asm — HW1 Q4(d): shamt is 5 bits, range 0..31
        .text
main:   addi    $s2, $zero, 4095       # $s2 = 0x00000FFF
# remove the leading "# " on the next line, then Run, to see the rejection:
# sll     $s5, $s2, 0x26        # INVALID: 0x26 = 38, too wide for 5 bits
        sll     $s5, $s2, 31           # fix, part 1: shift by 31...
        sll     $s5, $s5, 7            # fix, part 2: ...then 7 more, 38 in total
        add     $a0, $s5, $zero        # print the proof
        addi    $v0, $zero, 1
        syscall
        addi    $v0, $zero, 10
        syscall
#+END_SRC

#+RESULTS:
:0

The rejection: "shift amount 38 must be 0..31". The source says =0x26=, which is 38 decimal, and =shamt= is 5 bits. The fix spells the intent as two shifts, 31 then 7 — 38 positions in total — and the printed =0= shows what 38 positions do to a 32-bit register: every bit falls off the left end.

Exam angle: HW1 Q4 wants three parts per item — valid or not, one sentence saying why, one corrected instruction. Name the field and its width in that sentence.

* Branch and jump offset drills

Mental model: a branch stores no address. It stores a count of words from =PC+4= to the target, in two's complement, and the hardware shifts it left two at execution. A jump stores 26 bits of the target's word address — the low two bits are dropped because an aligned target always ends in =00=. The top four bits of the final jump address come from =(PC+4)=.

Predict three fields before running: the backward =bne= (DRILL A), the =j= (DRILL B), the forward =beq= (DRILL C). Counting rule: the offset counts machine words between =PC+4= and the label, and it is negative when the label sits earlier in memory.

#+NAME: offset-drill
#+BEGIN_SRC mips
# offset-drill.asm — predict three encoded offsets, then read the listing
        .text
main:   addi    $t0, $zero, 3          # counter = 3
        addi    $t1, $zero, 0          # acc = 0
again:  addi    $t1, $t1, 10           # acc += 10
        addi    $t0, $t0, -1           # counter--
        bne     $t0, $zero, again      # DRILL A (backward): predict the imm
        j       done                   # DRILL B (jump): predict the 26-bit field
        addi    $t1, $t1, 1000         # dead if your predictions hold
done:   beq     $zero, $zero, fin      # DRILL C (forward): predict the imm
        addi    $t1, $t1, 7000         # dead if your predictions hold
fin:    add     $a0, $t1, $zero        # print acc: it proves all three
        addi    $v0, $zero, 1
        syscall
        addi    $v0, $zero, 10
        syscall
#+END_SRC

#+RESULTS:
:30

After =Run=, check yourself against the listing. The low four hex digits of each branch word are the encoded offset — backward shows as =FF..=, two's complement. For the =j=, the top six bits hold opcode 2 and the low 26 bits are the field; shift the field left two to recover the byte address of =done=. The printed =30= is the behavior proof: three loop iterations at 10 each, both dead lines skipped.

Exam angle: the T4 exercises drill exactly this, forward and backward. The classic distractors count from =PC= instead of =PC+4=, giving =+6= where the answer is =+5=, or =−5= where the answer is =−6=. Ranges: a branch offset is a signed 16-bit word count, so branches reach ±128 KiB around =PC+4=; the jump field is unsigned and cannot leave the 256 MiB region that contains =PC+4=.

* Stack and procedure drills

Mental model: the stack is ordinary memory plus a convention. =$sp= starts at =0x7fffeffc= and grows down. To push, decrement =$sp= and then =sw=. To pop, =lw= and then increment. And =jal= does two things in that order: =$ra= receives =PC+4=, then the jump happens. Every T6 question reduces to those sentences.

Predict three values in the block below. PREDICT 1: =$ra= right after the =jal= — count the words that precede it. PREDICT 2: =$sp= after the push. PREDICT 3: =$sp= after the pop. Then verify with breakpoints: click the gutter number on the first =sw= line, =Run=, and read =$sp= and =$ra= in the =Registers= panel; continue, break on the =jr= line, and read the restored =$sp=.

#+NAME: stack-drill
#+BEGIN_SRC mips
# stack-drill.asm — predict $sp and $ra at the marked lines
        .text
main:   addi    $s0, $zero, 7          # $s0 = 7, must survive the call
        addi    $s1, $zero, 9          # $s1 = 9, must survive the call
        addi    $a0, $zero, 21         # argument: double(21)
        jal     double                 # PREDICT 1: $ra after this line runs
        add     $a0, $v0, $zero        # print the result
        addi    $v0, $zero, 1
        syscall
        addi    $a0, $zero, 10         # '\n'
        addi    $v0, $zero, 11
        syscall
        add     $a0, $s0, $zero        # print $s0: still 7 after the call
        addi    $v0, $zero, 1
        syscall
        addi    $v0, $zero, 10
        syscall
double: addi    $sp, $sp, -8           # PREDICT 2: $sp after this line
        sw      $s1, 4($sp)            # spill callee-saved $s1
        sw      $s0, 0($sp)            # spill callee-saved $s0
        add     $s0, $a0, $zero        # clobber $s0 on purpose
        add     $s1, $s0, $s0          # $s1 = 2 * a0
        add     $v0, $s1, $zero        # result goes in $v0
        lw      $s0, 0($sp)            # restore $s0
        lw      $s1, 4($sp)            # restore $s1
        addi    $sp, $sp, 8            # PREDICT 3: $sp after this line
        jr      $ra                    # return to the PREDICT 1 address
#+END_SRC

#+RESULTS:
:42
:7

What the run proves. The =Output= prints =42= — the doubled argument came back in =$v0= — and then =7= — =$s0= survived the call, because the callee spilled and restored it. Count memory accesses on both sides while you are here. Data half: two =sw= and two =lw=, four in total; every =add= and =addi= around them touches registers only. Instruction half: every executed instruction is one instruction fetch — this run executed 25 of them, so the full count is 25 fetches + 4 data = 29. That is A7 in its full form, and the rule matches HW1 Q8's official answer of 10 = 7 instruction fetches + 3 data accesses: count the executed =lw= and =sw= for the data half, then add one fetch per executed instruction for the instruction half. Only =lw= and =sw= reach data memory, and address arithmetic is free.

One more listing read. The =jr $ra= word is =0x03E00008=: opcode 0, rs 31, funct 8. A tutorial slide prints =0x03E00010= for this instruction — a known typo, since funct =0x10= is not a return. The listing column is the ground truth.

Exam angle: T6 in full. The flagship trap is the nested call — a second =jal= overwrites =$ra=, so a non-leaf callee must spill =$ra= first. This callee is a leaf and needs no =$ra= spill, but it dutifully saves the =$s= registers it touches: the caller saves =$t=, =$a=, =$v=; the callee saves =$s=.

* Memorize versus look up

The exams are closed-book with no calculator, and the course maintains a MIPS reference card for lookup during graded work. Assume the card is on the desk: field layouts, opcode and funct values, and the register table live there. What the card cannot do is choose the method. The split, condensed:

| Memorize — methods, ranges, conventions | Look up — the card has it |
|---+---|
| Decode order: opcode 0 means R-type, then funct decides | Opcode and funct value for each mnemonic |
| Branch offset = (target − (PC+4)) / 4, counted in words | Exact field bit positions 31–26, 25–21, 20–16, 15–11, 10–6, 5–0 |
| Jump field = target >> 2; upper 4 bits come from (PC+4) | The full register table, with the preserved-across-a-call column |
| Sign-extend: addi, slti, load/store offsets. Zero-extend: andi, ori, xori | The Verilog operation column |
| Signed immediate −32768..32767; shamt 0..31; there is no subi | The pseudo-instruction list |
| Register roles: $t caller-saved, $s callee-saved, $a and $v carry arguments and results, $sp grows down, $ra returns | Floating-point instruction encodings |
| $t0 through $t7 are 8 to 15; $s0 through $s7 are 16 to 23 | |
| Push: decrement $sp then sw. Pop: lw then increment. jal writes $ra before jumping | |

Out of scope on purpose: IEEE 754 encode and decode (A13, A14) and pure performance arithmetic — CPI, execution time, speedup, Amdahl's law (A15). Those are number-systems and performance topics, and they live in the midterm-prep book. The MIPS-relevant seams already appeared in this series: constant building above, and the pipeline and cache arithmetic on Multi-Cycle and the Pipeline, Hazards, Forwarding, Stalls, and The Memory Hierarchy.
