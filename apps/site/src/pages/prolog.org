#+SUBTITLE: Unification, SLD resolution, backtracking, and cut on a steppable Prolog engine

* Facts and queries

In Prolog you write facts and rules instead of imperative steps. =likes(ada, prolog).= states a fact, and =?- likes(ada, X).= asks Prolog to find a binding for the capitalized variable =X= that makes it true.

Run the block and look at *Bindings*: it finds =X = prolog= and stops. Run it again to backtrack to the next match (=X = lisp=), and a third time to get =No.=. The unifier checks for cycles (occurs check), so =?- X = f(X).= fails cleanly instead of looping forever.

#+NAME: facts-and-queries
#+BEGIN_SRC prolog
likes(ada, prolog).
likes(ada, lisp).
likes(bob, prolog).
?- likes(ada, X).
#+END_SRC

#+RESULTS:
: Yes.
: X = prolog

* Rules and the goal stack

=:-= means "if", so =grandparent(X, Z) :- parent(X, Y), parent(Y, Z).= breaks one goal into two subgoals. Step through the block with *Goal stack* open: Prolog always resolves the leftmost goal first, unifying =Y = mary= and then proving =parent(mary, ann)=. When the goal stack empties, you have an answer.

#+NAME: rules-and-conjunction
#+BEGIN_SRC prolog
parent(tom, mary).
parent(mary, ann).
parent(mary, pat).
grandparent(X, Z) :- parent(X, Y), parent(Y, Z).
?- grandparent(tom, G).
#+END_SRC

#+RESULTS:
: Yes.
: G = ann

* Recursive =member= and =findall=

=member/2= is not built into this kernel, so we define it in two clauses: =E= is in a list if it matches the head =[E|_]=, or if it is in the tail =T=. =findall/3= runs a goal through every possible backtrack and collects all matches into a list (=Es=) in clause order. (=E = E= just shows the template variable stayed unbound outside =findall=.)

#+NAME: member-by-recursion
#+BEGIN_SRC prolog
member(E, [E|_]).
member(E, [_|T]) :- member(E, T).
?- findall(E, member(E, [ada, bob, cy]), Es).
#+END_SRC

#+RESULTS:
: Yes.
: E = E
: Es = [ada, bob, cy]

* Running =append= backwards

Because predicates are relations rather than one-way functions, =append/3= can split a list just as easily as it joins two lists. Step through the query below with *Choice points* open: every recursive step saves an alternative on the choice-point stack, and backtracking unwinds them one by one to produce all three splits of =[1, 2]=.

#+NAME: append-generates
#+BEGIN_SRC prolog
append([], Ys, Ys).
append([X|Xs], Ys, [X|Zs]) :- append(Xs, Ys, Zs).
?- findall(p(Xs, Ys), append(Xs, Ys, [1, 2]), Ps).
#+END_SRC

#+RESULTS:
: Yes.
: Xs = Xs
: Ys = Ys
: Ps = [p([], [1, 2]), p([1], [2]), p([1, 2], [])]

* Pruning search with cut (=!=)

The cut operator =!= always succeeds and immediately drops every choice point created since the current predicate started. In =max3=, once =X >= Y= succeeds and hits =!=, Prolog commits to that clause and never tries the fallback, so =WithCut= is =[5]=. Without the cut, =maxu= backtracks into the second clause too and returns =[5, 3]=.

#+NAME: cut-prunes
#+BEGIN_SRC prolog
max3(X, Y, X) :- X >= Y, !.
max3(_, Y, Y).
maxu(X, Y, X) :- X >= Y.
maxu(_, Y, Y).
?- findall(M, max3(5, 3, M), WithCut).
?- findall(M, maxu(5, 3, M), WithoutCut).
#+END_SRC

#+RESULTS:
: Yes.
: M = M
: WithCut = [5]
: Yes.
: M = M
: WithoutCut = [5, 3]
