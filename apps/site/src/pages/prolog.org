#+TITLE: Prolog, Search Exposed
#+SUBTITLE: Unification, SLD resolution, choice points, backtracking, and cut on a steppable Prolog engine

In Prolog you declare *facts* and *rules*, then pose a query (=?- ...=). Rather than executing statements top to bottom, the engine searches for variable bindings that satisfy every goal using *SLD resolution* and depth-first backtracking. Click *Step* or set gutter breakpoints to inspect *Goal stack*, *Choice points*, *Search* (the exact transition on the last step: =resolve=, =mismatch=, =backtrack=, =cut=, =solution=), *Bindings*, and *Output*.

* Facts, unification, and backtracking

=likes(ada, prolog).= states a fact; =?- likes(ada, X).= asks the unifier to bind the capitalized variable =X=. Run =facts-and-queries= once to get ~X = prolog~, then click *Run* again to trigger backtracking to ~X = lisp~, and a third time to exhaust the search (=No.=).

#+NAME: facts-and-queries
#+BEGIN_SRC prolog
likes(ada, prolog).
likes(ada, lisp).
likes(bob, prolog).
?- likes(ada, X).
#+END_SRC

#+RESULTS:
: Yes.
: X = prolog

*Try editing:* replace the query with =?- X = f(X).= and run — this engine enables the *occurs check*, so cyclic unification fails cleanly with =No.= instead of looping forever.

* Rules, the *Goal stack*, and SLD search

A rule =grandparent(X, Z) :- parent(X, Y), parent(Y, Z).= rewrites one goal into two subgoals. Prolog always resolves the leftmost goal first, pushing a choice point whenever multiple clauses could match.

* Relations run backwards: splitting lists with =append/3=

Because Prolog predicates are *relations* rather than one-way functions, =append/3= splits a list just as effortlessly as it concatenates two lists. Step through =append-generates= with *Choice points* open: every recursive call pushes an alternative onto *Choice points*, and =findall/3= drives backtracking through all three splits of =[1, 2]=.

#+NAME: append-generates
#+BEGIN_SRC prolog
append([], Ys, Ys).
append([X|Xs], Ys, [X|Zs]) :- append(Xs, Ys, Zs).
?- findall(p(Xs, Ys), append(Xs, Ys, [1, 2]), Ps).
#+END_SRC

#+RESULTS:
: Yes.
: Xs = Xs
: Ys = Ys
: Ps = [p([], [1, 2]), p([1], [2]), p([1, 2], [])]

*Try editing:* change =[1, 2]= to =[1, 2, 3]= and re-run — =Ps= now collects all 4 splits of the 3-element list.

* Pruning search with cut (=!=)

The cut operator =!= always succeeds and immediately discards every choice point created since the current predicate was entered. Contrast =max3= (which commits once ~X >= Y~ succeeds) with =maxu= (which lacks =!= and backtracks into the fallback clause too).

#+CAPTION: Cut (!) discards the choice point to clause 2 once X >= Y succeeds
#+BEGIN_SRC typst :results svg
#set text(size: 9pt)
#import "@preview/fletcher:0.5.8": diagram, node, edge

#let boxnode(pos, body, hl: false, cut: false) = node(
  pos, body, shape: rect, inset: 5pt, width: 108pt,
  stroke: 0.8pt + if hl { rgb("#1A9988") } else if cut { rgb("#C2553F") } else { luma(130) },
  fill: if hl { rgb("#F2F8F6") } else if cut { rgb("#FDF3F1") } else { white },
)

#diagram(
  spacing: (18pt, 12pt),
  boxnode((1, 0), text(font: "DejaVu Sans Mono", size: 8pt)[max3(5, 3, M)]),
  boxnode((0, 1.2), [*clause 1: 5 >= 3, !* #linebreak() #text(size: 8pt)[commits -> M = 5]], hl: true),
  boxnode((2, 1.2), [*clause 2: pruned* #linebreak() #text(size: 8pt)[choice point dropped]], cut: true),
  edge((1, 0), (0, 1.2), "->", stroke: 0.9pt + rgb("#1A9988")),
  edge((1, 0), (2, 1.2), "->", stroke: (paint: rgb("#C2553F"), thickness: 0.8pt, dash: "dashed"), label: [#text(size: 8pt)[cut!]], label-fill: white),
)
#+END_SRC

#+NAME: cut-prunes
#+BEGIN_SRC prolog
max3(X, Y, X) :- X >= Y, !.
max3(_, Y, Y).
maxu(X, Y, X) :- X >= Y.
maxu(_, Y, Y).
?- findall(M, max3(5, 3, M), WithCut).
?- findall(M, maxu(5, 3, M), WithoutCut).
#+END_SRC

#+RESULTS:
: Yes.
: M = M
: WithCut = [5]
: Yes.
: M = M
: WithoutCut = [5, 3]

*Try editing:* step through =max3(5, 3, M)= and watch *Search* report =cut= while *Choice points* drops to zero. Then remove =, != from line 1 and re-run to see =WithCut= turn into =[5, 3]=.
