* One data structure: the dual-part table

Lua has no separate list, dictionary, or object type — every compound structure is a *table* with an array part for consecutive integer keys starting at =1= and a hash part for everything else. The length operator =#t= measures only the array border and ignores hash keys.

* Multiple returns, parallel assignment, and truthiness

Functions return multiple values directly without allocating a tuple. A call in the last position of an assignment expands to all its return values (~local lo, hi = minmax(xs)~); wrapping it in parentheses =(minmax(xs))= truncates it to one value. Because Lua evaluates the entire right-hand side before writing the left, ~a, b = b, a~ swaps in place.

#+NAME: multiple-returns
#+BEGIN_SRC lua
local function minmax(t)
  local lo, hi = t[1], t[1]
  for i = 2, #t do
    if t[i] < lo then lo = t[i] end
    if t[i] > hi then hi = t[i] end
  end
  return lo, hi
end

local xs = {3, 1, 4, 1, 5}
local lo, hi = minmax(xs)
local only = minmax(xs)
print(lo, hi, only, (minmax(xs)))
local a, b = 1, 2
a, b = b, a
print(a, b)
#+END_SRC

#+RESULTS:
: 1	5	1	1
: 2	1

*Try editing:* set a breakpoint on line 4 and inspect *Locals* and *Call stack* as =minmax= scans =xs=. Also test Lua's truthiness rule: unlike [[file:python.org][Python]], [[file:c.org][C]], or [[file:javascript.org][JavaScript]], both =0= and =""= are truthy — only =nil= and =false= are falsy.

* Integers vs floats in *Values*

Lua 5.4 keeps integer and float subtypes distinct: =/= always yields a float (~7 / 2 = 3.5~), while =//= performs floor division toward $-oo$ (so ~-7 // 2 = -4~, not =-3=). Modulo =%= takes the sign of the divisor. Run =ints-and-floats= and inspect *Values* to see each binding's exact subtype tag.

#+NAME: ints-and-floats
#+BEGIN_SRC lua
local exact = 7 / 2
local floored = 7 // 2
local neg_floor = -7 // 2
global_tag = 1 == 1.0
print(exact, floored, neg_floor, global_tag)
#+END_SRC

#+RESULTS:
: 3.5	3	-4	true

* Prototype inheritance via =__index= metatables

Lua builds object-oriented dispatch from one mechanism: if a key lookup misses on a table, Lua checks its metatable's =__index= field. If =__index= is another table, lookup continues up the chain; if it is a function, Lua calls it with =(table, key)=. Colon syntax =rex:greet()= is pure sugar for =rex.greet(rex)=.

#+NAME: metatables
#+BEGIN_SRC lua
local Animal = {}
function Animal:greet() return self.sound .. "!" end

local Dog = {}
Animal.__index = Animal
setmetatable(Dog, {__index = Animal})

local Dog2 = {}
Dog.__index = Dog
setmetatable(Dog2, {__index = Dog})

local rex = {sound = "woof"}
setmetatable(rex, {__index = Dog2})

local fallback = setmetatable({}, {__index = function(t, k) return k .. "?" end})
print(rex:greet())
print(fallback.anything)
#+END_SRC

#+RESULTS:
: woof!
: anything?
