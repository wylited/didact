#+TITLE: Lisp from Cons Cells Up
#+SUBTITLE: Cons pairs, quoting, tail calls, closures, and macros on a steppable Scheme interpreter

* Cons cells and the heap

Every value in this Lisp is either an atom (number, symbol, =#t=/=#f=, string, ='()=) or a *cons cell*, which is just a pair of two slots called =car= and =cdr=. A list like =(1 2)= is nothing more than =(cons 1 (cons 2 '()))=.

Run the block below and look at the *Heap* panel. Each cell gets a fixed address (=0x0000=, =0x0010=, ...). =(cons 2 '())= allocates the first cell, and =(cons 1 ...)= allocates a second cell whose =cdr= points to it. (The heap caps at 4,096 cells with no garbage collector.) When a cell's =cdr= is not another list, it prints as a dotted pair like =(1 . 2)=.

#+NAME: cons-101
#+BEGIN_SRC lisp
(define lst (cons 1 (cons 2 '())))
(display (car lst))
(newline)
(display (cdr lst))
(newline)
(display lst)
(newline)
(display (cons 1 2))
(newline)
#+END_SRC

#+RESULTS:
: 1
: (2)
: (1 2)
: (1 . 2)

* Quote and quasiquote

Prefixing a form with ='= stops Lisp from evaluating it and hands you the list structure itself. Quasiquote (backquote) does the same thing except you can unquote pieces inside it: =,= evaluates a single expression, and =,@= evaluates a list and splices its elements in. Step through the block to watch the interpreter expand quasiquote into regular =cons= and =append= calls on the *Control stack*.

#+NAME: quote-vs-quasiquote
#+BEGIN_SRC lisp
(display '(1 2 3))
(newline)
(define x 10)
(display `(x is ,x and doubled is ,(* 2 x)))
(newline)
(display `(start ,@(list 1 2 3) end))
(newline)
#+END_SRC

#+RESULTS:
: (1 2 3)
: (x is 10 and doubled is 20)
: (start 1 2 3 end)

* Tail calls vs growing the stack

Compare =sum-to= and =fact= below with the *Control stack* panel open. =fact= still has to multiply by =n= after =(fact (- n 1))= returns, so every call leaves a waiting frame on the stack. =sum-to= finishes by calling itself in tail position, so the interpreter reuses the current frame instead of stacking a new one. That is why =(sum-to 100000 0)= runs in flat O(1) stack space. (Total reductions cap at 1,000,000 so infinite recursion stops cleanly.)

#+NAME: tail-calls
#+BEGIN_SRC lisp
(define (sum-to n acc)
  (if (= n 0)
      acc
      (sum-to (- n 1) (+ n acc))))
(display (sum-to 100000 0))
(newline)
(define (fact n)
  (if (= n 0)
      1
      (* n (fact (- n 1)))))
(display (fact 10))
(newline)
#+END_SRC

#+RESULTS:
: 5000050000
: 3628800

* Closures

Every =lambda= hangs on to the environment where it was created. Calling =make-counter= twice creates two separate =let= frames, each with its own =n=, so =a= and =b= count independently. Open the *Environment* panel while stepping to watch the scope chain (=a -> let -> make-counter -> global=) and see =set!= mutate =n=.

#+NAME: closures
#+BEGIN_SRC lisp
(define (make-counter)
  (let ((n 0))
    (lambda () (set! n (+ n 1)) n)))
(define a (make-counter))
(define b (make-counter))
(a) (a)
(display (list (a) (b)))
(newline)
#+END_SRC

#+RESULTS:
: (3 1)

By the way, =eq?= compares heap addresses (so =(eq? (list 1 2) (list 1 2))= is =#f=), while =equal?= walks both lists and compares values (=#t=).

* Macros rewrite syntax before evaluation

A macro receives its arguments unevaluated and returns new code for the evaluator to run. =my-if= rewrites itself into =cond=, and =swap!= expands into a =let= block that swaps two variables in place (using an unhygienic local named =tmp=). Call =macroexpand-1= to see the rewritten form without executing it.

#+NAME: macros
#+BEGIN_SRC lisp
(define-macro (my-if c t e) `(cond (,c ,t) (else ,e)))
(display (macroexpand-1 '(my-if (= 1 1) 'yes 'no)))
(newline)
(display (my-if (= 1 2) 'yes 'no))
(newline)
(define-macro (swap! x y) `(let ((tmp ,x)) (set! ,x ,y) (set! ,y tmp)))
(define p 1)
(define q 2)
(swap! p q)
(display (list p q))
(newline)
#+END_SRC

#+RESULTS:
: (cond ((= 1 1) (quote yes)) (else (quote no)))
: no
: (2 1)

Try running =(append '(1 2) '(3 4))= and testing with =eq?= whether the tail list is shared, or write your own macro and inspect it with =macroexpand-1=.
