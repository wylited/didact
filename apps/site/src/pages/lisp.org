#+TITLE: Lisp from Cons Cells Up
#+SUBTITLE: Cons-cell heap addresses, tail-call frame reuse, closures, and macros on a steppable Scheme interpreter

Every value in this pure-TypeScript Scheme interpreter is either an atom (number, symbol, ~#t~ / ~#f~, string, ='()=) or a *cons cell* — a two-slot pair =(car . cdr)= allocated at a fixed heap address. Click *Step* or set gutter breakpoints to inspect *Heap* (every allocated cell at =0x0000=, =0x0010=, ...), *Environment* frames, *Control stack*, and *Output*.

* Cons cells and pointer identity

A proper list like =(1 2)= is just a chain of cons cells ending in ='()=: =(cons 1 (cons 2 '()))=. When the final =cdr= is another atom instead of ='()=, Lisp prints a dotted pair like =(1 . 2)=.

Run =cons-101= and look at *Heap*: =(cons 2 '())= allocates cell =0x0000= first, then =(cons 1 ...)= allocates =0x0010= pointing to =0x0000=.

#+BEGIN_SRC lisp
(define lst (cons 1 (cons 2 '())))
(display (car lst)) (newline)
(display (cdr lst)) (newline)
(display lst) (newline)
(display (cons 1 2)) (newline)
(display (eq? (list 1 2) (list 1 2))) (newline)

*Try editing:* =eq?= compares heap addresses (so two fresh =(list 1 2)= allocations are =#f=), whereas =equal?= walks both trees structurally (=#t=). Test =(define b (cdr lst)) (eq? b (cdr lst))= to see structural sharing return =#t=.

* Tail calls vs growing the *Control stack*

In =fact=, the outer multiplication =(* n ...)= must wait for =(fact (- n 1))= to return, so every recursive call pushes a pending continuation frame onto *Control stack* ($O(n)$ space). In =sum-to=, the recursive call is the very last operation (tail position), so the interpreter reuses the current frame in $O(1)$ space.

#+CAPTION: Non-tail recursion stacks waiting multiply frames; tail recursion reuses one frame

#+NAME: tail-calls
#+BEGIN_SRC lisp
(define (sum-to n acc)
  (if (= n 0)
      acc
      (sum-to (- n 1) (+ n acc))))
(display (sum-to 100000 0)) (newline)

(define (fact n)
  (if (= n 0)
      1
      (* n (fact (- n 1)))))
(display (fact 10)) (newline)
#+END_SRC

#+RESULTS:
: 5000050000
: 3628800

*Try editing:* set a breakpoint on line 10 (=* n (fact (- n 1))=) and click *Run* repeatedly to watch *Control stack* grow deeper on every recursive call, then contrast it with a breakpoint on line 4 where the stack depth never grows.

* Lexical closures and private environments

Every =lambda= closes over the environment frame where it was created. Calling =make-counter= twice allocates two independent =let= frames, so =a= and =b= mutate separate =n= bindings.

#+NAME: closures
#+BEGIN_SRC lisp
(define (make-counter)
  (let ((n 0))
    (lambda () (set! n (+ n 1)) n)))
(define a (make-counter))
(define b (make-counter))
(a) (a)
(display (list (a) (b))) (newline)
#+END_SRC

#+RESULTS:
: (3 1)

*Try editing:* step through =(a)= and =(b)= to watch the environment chain in the panel point to two distinct =let= frames. Compare this with [[file:elisp.org][Emacs Lisp's dynamic vs lexical binding]].

* Quasiquote and syntax-rewriting macros

A macro receives its arguments *unevaluated* as cons lists and returns new code for the evaluator to run. Quasiquote (=`=) builds templates where =,= inserts one evaluated value and =,@= splices a list. =macroexpand-1= shows the generated code without executing it.

#+NAME: macros
#+BEGIN_SRC lisp
(define-macro (my-if c t e) `(cond (,c ,t) (else ,e)))
(display (macroexpand-1 '(my-if (= 1 1) 'yes 'no))) (newline)
(display (my-if (= 1 2) 'yes 'no)) (newline)

(define-macro (swap! x y) `(let ((tmp ,x)) (set! ,x ,y) (set! ,y tmp)))
(define p 1)
(define q 2)
(swap! p q)
(display (list p q)) (newline)
#+END_SRC

#+RESULTS:
: (cond ((= 1 1) (quote yes)) (else (quote no)))
: no
: (2 1)

*Try editing:* rename =p= to =tmp= and call =(swap! tmp q)= — watch classic unhygienic variable capture break the swap because =swap!='s internal =tmp= shadows the caller's =tmp=!

* Exercise: splice a list with quasiquote

Use quasiquote (=`=) and unquote-splicing (=,@=) to splice =mid= inside =(10 ... 40)= so the block prints =(10 20 30 40)=.

#+NAME: ex-splice
#+EXERCISE: Splice mid into (10 20 30 40) using ,@
#+CHECK: (10 20 30 40)
#+BEGIN_SRC lisp
(define mid (list 20 30))
(display `(10 ,mid 40)) (newline)
#+END_SRC

#+BEGIN_HINT
Replace =,mid= with =,@mid= so =(20 30)= is spliced flat instead of nested as =(10 (20 30) 40)=.
#+END_HINT

#+BEGIN_SOLUTION
#+BEGIN_SRC lisp
(define mid (list 20 30))
(display `(10 ,@mid 40)) (newline)
#+END_SRC
#+END_SOLUTION
