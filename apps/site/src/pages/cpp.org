Hit Run on any block and clang++ compiles it against =libc++= with this exact command:

=clang++ -std=c++20 -fno-exceptions lesson.cpp -o lesson.wasm=

The bundled =libc++abi= is built without exception support, so =-fno-exceptions= is on. If you write =throw=, clang rejects it at compile time on that line. Everything else is real C++20 running on WebAssembly via a minimal WASI shim (stdout and exit codes work; filesystem calls fail cleanly). The right-hand panel shows the build log, exit status, binary size, compile time, and the first 256 bytes of the linked =.wasm= output.

* RAII and destructor order

C++ does not need =finally= blocks because local objects run their destructors automatically the moment they leave scope, always in reverse order of construction. Here =inner= is destroyed at the closing brace before execution even reaches the next =printf=, and =outer= cleans up when =main= returns.

#+NAME: raii
#+BEGIN_SRC cpp
#include <cstdio>

struct Trace {
  const char* name;
  explicit Trace(const char* n) : name(n) {
    std::printf("construct %s\n", name);
  }
  ~Trace() { std::printf("destroy %s\n", name); }
};

int main() {
  Trace outer("outer");
  {
    Trace inner("inner");
    std::printf("--- inner scope ends ---\n");
  }
  std::printf("--- inner already gone ---\n");
  return 0;
}
#+END_SRC

#+RESULTS:
: construct outer
: construct inner
: --- inner scope ends ---
: destroy inner
: --- inner already gone ---
: destroy outer

* How =std::vector= grows

When =push_back= runs out of space, =std::vector= allocates a new buffer twice as big, moves the existing elements across, and frees the old one. Watch =capacity= jump =1, 2, 4, 8= while =size= ticks up by one. Push 4 does not reallocate because slot 4 was already reserved.

#+NAME: vector-growth
#+BEGIN_SRC cpp
#include <vector>
#include <cstdio>

int main() {
  std::vector<int> v;
  for (int i = 1; i <= 5; i++) {
    v.push_back(i * i);
    std::printf("push %2d: size=%zu capacity=%zu\n", i * i, v.size(), v.capacity());
  }
  for (size_t i = 0; i < v.size(); ++i)
    std::printf(i == 0 ? "%d" : " %d", v[i]);
  std::printf("\n");
  return 0;
}
#+END_SRC

#+RESULTS:
: push  1: size=1 capacity=1
: push  4: size=2 capacity=2
: push  9: size=3 capacity=4
: push 16: size=4 capacity=4
: push 25: size=5 capacity=8
: 1 4 9 16 25

* Templates generate real functions per type

=max<T>= is not erased at runtime. Calling it with =int=, =double=, and =char= makes clang emit three separate compiled functions, one per type, with zero boxing or virtual dispatch.

#+NAME: templates
#+BEGIN_SRC cpp
#include <cstdio>

template <typename T>
T max(T a, T b) {
  return a > b ? a : b;
}

int main() {
  std::printf("max(3, 9)        = %d\n", max(3, 9));
  std::printf("max(2.5, 2.25)   = %.1f\n", max(2.5, 2.25));
  std::printf("max('a', 'z')    = %c\n", max('a', 'z'));
  return 0;
}
#+END_SRC

#+RESULTS:
: max(3, 9)        = 9
: max(2.5, 2.25)   = 2.5
: max('a', 'z')    = z

* References vs pointers

Both swaps mutate =x= and =y= in place. The reference version (=int&=) cannot be null and cannot be rebound to another variable, so you pass =x, y= directly. The pointer version (=int*=) makes the indirection explicit with =&= at the call site and =*= inside the body.

#+NAME: refs-vs-pointers
#+BEGIN_SRC cpp
#include <cstdio>

void swapRef(int& a, int& b) {
  int t = a; a = b; b = t;
}

void swapPtr(int* a, int* b) {
  int t = *a; *a = *b; *b = t;
}

int main() {
  int x = 1, y = 2;
  swapRef(x, y);
  std::printf("after swapRef(x, y): x=%d y=%d\n", x, y);
  swapPtr(&x, &y);
  std::printf("after swapPtr(&x, &y): x=%d y=%d\n", x, y);
  return 0;
}
#+END_SRC

#+RESULTS:
: after swapRef(x, y): x=2 y=1
: after swapPtr(&x, &y): x=1 y=2

* Lambda captures: copy vs reference

=[base]= copies =10= into =addBase= at the moment the lambda is created, so setting =base = 100= later does nothing to it. =[&counter]= grabs a live reference instead, so calling =bump()= actually increments =counter=.

#+NAME: lambdas
#+BEGIN_SRC cpp
#include <cstdio>

int main() {
  int base = 10;
  auto addBase = [base](int x) { return base + x; };
  int counter = 0;
  auto bump = [&counter]() { ++counter; };

  std::printf("addBase(5) = %d\n", addBase(5));
  bump();
  bump();
  bump();
  std::printf("counter after 3 bumps = %d\n", counter);
  base = 100;
  std::printf("after base = 100, addBase(5) = %d (copied at capture!)\n", addBase(5));
  return 0;
}
#+END_SRC

#+RESULTS:
: addBase(5) = 15
: counter after 3 bumps = 3
: after base = 100, addBase(5) = 15 (copied at capture!)
