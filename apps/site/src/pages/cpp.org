* Deterministic cleanup with RAII

C++ ties resource lifetimes to lexical scopes instead of a garbage collector or =finally= blocks. Local objects construct top-to-bottom and destroy automatically in reverse (LIFO) order the moment execution leaves their enclosing braces.

#+NAME: raii
#+BEGIN_SRC cpp
#include <cstdio>

struct Trace {
  const char* name;
  explicit Trace(const char* n) : name(n) {
    std::printf("construct %s\n", name);
  }
  ~Trace() { std::printf("destroy %s\n", name); }
};

int main() {
  Trace outer("outer");
  {
    Trace inner("inner");
    std::printf("--- inner scope ends ---\n");
  }
  std::printf("--- inner already gone ---\n");
  return 0;
}
#+END_SRC

#+RESULTS:
: construct outer
: construct inner
: --- inner scope ends ---
: destroy inner
: --- inner already gone ---
: destroy outer

* Geometric growth in =std::vector=

When =push_back= fills a vector's heap buffer, =std::vector= allocates a new buffer twice as large ($1, 2, 4, 8, 16, dots.c$), moves existing elements over, and frees the old buffer. Because each doubling pays for all earlier copies, appending $n$ items stays amortized $O(1)$ per push.

#+NAME: vector-growth
#+BEGIN_SRC cpp
#include <vector>
#include <cstdio>

int main() {
  std::vector<int> v;
  const int* prev = nullptr;
  for (int i = 1; i <= 6; ++i) {
    v.push_back(i * i);
    bool moved = (prev != nullptr && v.data() != prev);
    prev = v.data();
    std::printf("push %2d: size=%zu capacity=%zu%s\n",
                i * i, v.size(), v.capacity(), moved ? "  (reallocated)" : "");
  }
  return 0;
}
#+END_SRC

#+RESULTS:
: push  1: size=1 capacity=1
: push  2: size=2 capacity=2  (reallocated)
: push  3: size=3 capacity=4  (reallocated)
: push  4: size=4 capacity=4
: push  5: size=5 capacity=8  (reallocated)
: push  6: size=6 capacity=8

* Templates, references, and lambda captures

Unlike boxed generics, =template <typename T>= instantiates a separate machine-code function for each concrete type at compile time. Similarly, a lambda's capture list =[...]= decides at compile time whether the closure object stores a *copy* (=[base]=) or a *reference* (=[&counter]=).

#+NAME: templates-and-lambdas
#+BEGIN_SRC cpp
#include <cstdio>

template <typename T>
T max_of(T a, T b) {
  return a > b ? a : b;
}

int main() {
  std::printf("max_of(3, 9) = %d, max_of(2.5, 2.25) = %.1f\n",
              max_of(3, 9), max_of(2.5, 2.25));

  int base = 10;
  auto add_base = [base](int x) { return base + x; };
  int counter = 0;
  auto bump = [&counter]() { ++counter; };

  bump();
  bump();
  base = 100;
  std::printf("counter=%d, add_base(5)=%d (captured 10 by value)\n",
              counter, add_base(5));
  return 0;
}
#+END_SRC

#+RESULTS:
: max_of(3, 9) = 9, max_of(2.5, 2.25) = 2.5
: counter=2, add_base(5)=15 (captured 10 by value)

*Try editing:* change =[base]= to =[&base]= and re-run — =add_base(5)= immediately jumps from =15= to =105= because the closure now reads the live variable. Compare this with [[file:javascript.org][closures in JavaScript]] and [[file:c.org][pointers in C]].
