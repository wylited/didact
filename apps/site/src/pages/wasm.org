#+TITLE: WebAssembly, Stepped Live
#+SUBTITLE: The i32 core of WAT: operand stack, binary opcodes, structured branches, and linear memory

This page runs a pure-TypeScript WebAssembly Text (WAT) interpreter for the =i32= core. Click *Step* or set gutter breakpoints to watch *Instructions* (showing real binary WebAssembly opcode bytes like =0x41= and =0x6a=), *Operand stack*, *Globals*, *Call stack*, *Memory*, and *Output*. These are the same binary opcodes emitted by clang in [[file:c.org][C]] and [[file:cpp.org][C++]].

* Arithmetic on an operand stack

WebAssembly has no CPU registers. Every instruction pushes onto or pops from a typed operand stack: =(i32.add (i32.const 20) (i32.const 22))= is just folded notation for pushing =20=, pushing =22=, then executing =i32.add= (=0x6a=).

Step through =stack-arith= below and watch *Operand stack* grow and shrink. Notice =i32= multiplication wraps modulo $2^(32)$ ($65536^2 equiv 0 (mod 2^(32))$), and signed division =i32.div_s= truncates toward zero ($-7 / 2 = -3$).

#+NAME: stack-arith
#+BEGIN_SRC wasm
(module
  (import "didact" "print" (func $print (param i32)))
  (func (export "main")
    (call $print (i32.add (i32.const 20) (i32.const 22)))
    (call $print (i32.mul (i32.const 65536) (i32.const 65536)))
    (call $print (i32.div_s (i32.const -7) (i32.const 2)))))
#+END_SRC

#+RESULTS:

* Locals and recursive frames on *Call stack*

Parameters and =(local ...)= slots are zero-initialized per call frame. Set a breakpoint on line 6 below and press *Run* repeatedly: watch *Call stack* stack up frames for =$n = 10, 9, \dots, 1= and then unwind as each =i32.mul= finishes.

#+NAME: factorial
#+BEGIN_SRC wasm
(module
  (import "didact" "print" (func $print (param i32)))
  (func $fact (param $n i32) (result i32)
    (if (result i32) (i32.le_s (local.get $n) (i32.const 1))
      (then (i32.const 1))
      (else (i32.mul (local.get $n) (call $fact (i32.sub (local.get $n) (i32.const 1)))))))
  (func (export "main")
    (call $print (call $fact (i32.const 10)))))
#+END_SRC

#+RESULTS:
: 3628800

* Structured control flow: =block=, =loop=, and =br=

WebAssembly forbids arbitrary =goto= so bytecode can be validated in a single linear pass. Instead, =br $label= jumps to opposite ends depending on the container: targeting a =block= exits forward (like =break=), while targeting a =loop= jumps backward to the header (like =continue=).

#+NAME: counted-loop
#+BEGIN_SRC wasm
(module
  (import "didact" "print" (func $print (param i32)))
  (func (export "main")
    (local $i i32)
    (local $sum i32)
    (block $done
      (loop $again
        (br_if $done (i32.gt_s (local.get $i) (i32.const 5)))
        (local.set $sum (i32.add (local.get $sum) (local.get $i)))
        (local.set $i (i32.add (local.get $i) (i32.const 1)))
        (br $again)))
    (call $print (local.get $sum))))
#+END_SRC

#+RESULTS:
: 15

*Try editing:* change =br $again= to =br $done= and step through — the loop now exits after one pass and prints =0=.

* Linear memory is a flat byte array

=(memory 1)= allocates one 64 KiB page of zero-initialized bytes. Multi-byte stores like =i32.store= write little-endian bytes, while =i32.load8_u= and =i32.load8_s= read a single byte unsigned or sign-extended (just like =lbu= and =lb= in [[file:riscv.org][RISC-V]]).

#+NAME: memory-bytes
#+BEGIN_SRC wasm
(module
  (import "didact" "print" (func $print (param i32)))
  (import "didact" "print_char" (func $print_char (param i32)))
  (memory 1)
  (func (export "main")
    (i32.store8 (i32.const 0) (i32.const 0x2A))
    (call $print_char (i32.load8_u (i32.const 0)))
    (call $print (i32.load8_u (i32.const 0)))))
#+END_SRC

#+RESULTS:
: *42

*Try editing:* replace =0x2A= with =0xFF= and compare =i32.load8_u= (=255=) against =i32.load8_s= (=-1=) while watching byte =ff= appear at =0x0000= in *Memory*.
