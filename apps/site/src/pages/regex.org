#+TITLE: Regex Without Backtracking
#+SUBTITLE: Compile patterns to a Thompson NFA and advance every active state together, one character per step

* How blocks work

The first non-comment line is a pattern between slashes (=/a(b|c)+d/=, no flags), and each line after it is a test input (=#= lines are comments; inputs decode =\n=, =\t=, =\r=, =\f=, =\v=, and =\\=).

Instead of backtracking like [[file:javascript.org][JS]] or [[file:python.org][Python]]'s =re=, this engine compiles the regex into a Thompson NFA and tracks the full *set* of active states at every character. Open *The machine* to see the compiled graph, *NFA states* to see which states are currently alive, and *Input* to watch the scan cursor move.

Literals match themselves, =.= matches anything except =\n=, character classes like =[a-z]= and =[^0-9]= take no escapes inside =[...]=, and =^=/=$= anchor to the start and end of the whole string.

#+NAME: regex-classes
#+BEGIN_SRC regex
# leftmost start, longest span — watch the Input panel
/[abc]+/
zzabcaz
zzz
#+END_SRC

#+RESULTS:
: match [2,6)
: no match

Unanchored searches try start positions =0, 1, 2, ...= until one succeeds, keeping the longest match from that earliest start (POSIX leftmost-longest).

#+BEGIN_SRC regex
/^b.*d$/
bcd
bcdex
xbcd
#+END_SRC

#+RESULTS:
: match [0,3)
: no match
: no match

* Alternation and quantifiers

In JS or Python, =/a|ab/= stops at ="a"= because the first branch matched. Here both branches stay alive in the same state set and the longest span wins, so =/a|ab/= and =/ab|a/= always agree.

#+NAME: regex-alt
#+BEGIN_SRC regex
/ab|a/
ab
a
xab
#+END_SRC

#+RESULTS:
: match [0,2)
: match [0,1)
: match [1,3)

Quantifiers include =*=, =+=, =?=, and counted ranges ={n}=, ={n,}=, ={n,m}=. Counted ranges expand into repeated states when compiled (=a{2,3}= becomes =a a a?=), which you can see directly in *The machine* panel. Escape literal braces with =\{=.

#+NAME: regex-quant
#+BEGIN_SRC regex
/a{2,3}/
aaaa
aa
a
#+END_SRC

#+RESULTS:
: match [0,3)
: match [0,2)
: no match

#+NAME: regex-optional
#+BEGIN_SRC regex
/colou?r/
color
colour
colr
#+END_SRC

#+RESULTS:
: match [0,5)
: match [0,6)
: no match

* Capturing groups

=(...)= captures half-open =[start, end)= spans numbered by opening paren; =(?:...)= groups without capturing. Repeated groups like =(ab)+= report their final iteration's span. Step through =regex-groups= with *Captures* open to watch the zero-width open and close marker states fire.

#+NAME: regex-groups
#+BEGIN_SRC regex
/(a(b))c/
xabc
#+END_SRC

#+RESULTS:
: match [1,4) groups: 1=[1,3) 2=[2,3)

#+NAME: regex-iterate
#+BEGIN_SRC regex
/(ab)+/
abab
ab
#+END_SRC

#+RESULTS:
: match [0,4) groups: 1=[2,4)
: match [0,2) groups: 1=[0,2)

* ASCII shorthands

=\d= is =[0-9]=, =\w= is =[A-Za-z0-9_]=, and =\s= is =[ \t\r\n\f\v]= (strict ASCII, with =\D=, =\W=, =\S= as their complements). Shorthands are not allowed inside =[...]= classes.

#+NAME: regex-words
#+BEGIN_SRC regex
/\w+ \d+/
room 404
room 4o4
#+END_SRC

#+RESULTS:
: match [0,8)
: match [0,6)

#+NAME: regex-space
#+BEGIN_SRC regex
/\s[a-z]+/
hi there
hi\tthere
#+END_SRC

#+RESULTS:
: match [2,8)
: match [2,8)

* What gets rejected at load time

Anything outside pure one-pass regular matching fails up front with its line number: backreferences (=\1=, =\k<name>=, because matching =ww= is not regular and needs unbounded memory), lookaround (=(?=...)=, =(?<=...)=), lazy quantifiers (=*?=), named groups, Unicode classes (=\p{L}=), and =\b=/=\B= word boundaries. Syntax errors like dangling =*=, reversed =[z-a]=, or bad ={2,1}= also point to the exact line.

* Why =/(a*)*/= stays linear

A backtracking engine chokes in O(2^n) time on =/(a*)*/= against 1,000 =a=s followed by =b=. A Thompson NFA merges duplicate states at every step, so each character does at most one pass over the state graph. All 1,001 characters finish in 1,001 steps (runs cap at 4,096 NFA states, 100,000 character steps, and 5,000,000 state visits).

#+BEGIN_SRC regex
/(a*)*/

#+END_SRC

#+RESULTS:
