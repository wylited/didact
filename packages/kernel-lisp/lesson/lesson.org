#+TITLE: Lisp from Cons Cells Up
#+SUBTITLE: Cons pairs, quoting, tail calls, closures, and macros on a steppable Scheme interpreter

* Everything is either an atom or a cons cell

Lisp's entire data model fits in two concepts: *atoms* (numbers, symbols like =x=, booleans =#t=/=#f=, strings, and the empty list ='()=) and *cons cells* — two-slot pairs holding a =car= (first slot) and a =cdr= (second slot).

A list like =(1 2)= is just a chain of cons cells ending in ='()=:

=(cons 1 (cons 2 '()))=

Run the block below and watch the *Heap* panel. Each cons cell gets a fixed address (=0x0000=, =0x0010=, ...). Evaluating =(cons 2 '())= allocates the first cell (=car= =2=, =cdr= =()=), and =(cons 1 ...)= allocates a second cell whose =cdr= points to the first. (This teaching heap holds 4,096 cells with no garbage collector, stopping with a clean error if it fills up.)

- =car= reads the first slot; =cdr= reads the second.
- If a cell's =cdr= is not a list, it prints as a *dotted pair* like =(1 . 2)=.

#+NAME: cons-101
#+BEGIN_SRC lisp
(define lst (cons 1 (cons 2 '())))
(display (car lst))
(newline)
(display (cdr lst))
(newline)
(display lst)
(newline)
(display (cons 1 2))
(newline)
#+END_SRC

#+RESULTS:
: 1
: (2)
: (1 2)
: (1 . 2)

* Quote and quasiquote: code as data

Putting ='= in front of an expression tells Lisp: *do not evaluate this — return the list structure as data*. Evaluating ='(1 2 3)= allocates three fresh cons cells on the heap.

*Quasiquote* (backquote) works like quote, except you can punch evaluation holes inside it:

- =,= (unquote) evaluates one expression and drops its value into place.
- =,@= (unquote-splicing) evaluates a list and splices its elements directly into the enclosing list.

Under the hood, the interpreter expands quasiquote into ordinary =cons= and =append= calls — single-step the block to watch that expansion on the *Control stack*.

#+NAME: quote-vs-quasiquote
#+BEGIN_SRC lisp
(display '(1 2 3))
(newline)
(define x 10)
(display `(x is ,x and doubled is ,(* 2 x)))
(newline)
(display `(start ,@(list 1 2 3) end))
(newline)
#+END_SRC

#+RESULTS:
: (1 2 3)
: (x is 10 and doubled is 20)
: (start 1 2 3 end)

* Recursion and why tail calls use O(1) stack

Look at the two recursive functions below:

- =fact= multiplies *after* the recursive call returns, so every call must leave a pending continuation on the *Control stack*.
- =sum-to= finishes by calling itself directly in *tail position* — there is nothing left to do when it returns. The interpreter replaces the current frame instead of pushing a new one, so =(sum-to 100000 0)= runs in constant stack space.

Open the *Control stack* panel and step through both to see =fact= grow frames while =sum-to= stays flat. (Runs are capped at 1,000,000 reductions so infinite recursion stops cleanly.)

#+NAME: tail-calls
#+BEGIN_SRC lisp
(define (sum-to n acc)
  (if (= n 0)
      acc
      (sum-to (- n 1) (+ n acc))))
(display (sum-to 100000 0))
(newline)
(define (fact n)
  (if (= n 0)
      1
      (* n (fact (- n 1)))))
(display (fact 10))
(newline)
#+END_SRC

#+RESULTS:
: 5000050000
: 3628800

* Closures: functions that keep their environment

Every =(lambda ...)= captures the environment where it was created. Each call to =make-counter= creates a fresh =let= frame holding its own =n=, so =a= and =b= maintain completely separate counts. Step through the calls with the *Environment* panel open to watch the scope chain (=a -> let -> make-counter -> global=) and see =set!= update =n= in place.

#+NAME: closures
#+BEGIN_SRC lisp
(define (make-counter)
  (let ((n 0))
    (lambda () (set! n (+ n 1)) n)))
(define a (make-counter))
(define b (make-counter))
(a) (a)
(display (list (a) (b)))
(newline)
#+END_SRC

#+RESULTS:
: (3 1)

Quick identity note: =eq?= checks whether two values point to the *same heap address* (so =(eq? (list 1 2) (list 1 2))= is =#f=), while =equal?= walks both structures and compares their contents (=#t=).

* Macros: functions that transform syntax

A macro runs *before* evaluation, taking unevaluated syntax as input and returning new code to evaluate. Below, =my-if= rewrites itself into a =cond= expression, and =swap!= expands into a =let= block that swaps two variables in place. Use =macroexpand-1= to inspect the generated code without running it.

Note: =define-macro= here is intentionally unhygienic — =swap!= uses a local variable named =tmp=, which works as long as the caller does not pass a variable also named =tmp=.

#+NAME: macros
#+BEGIN_SRC lisp
(define-macro (my-if c t e) `(cond (,c ,t) (else ,e)))
(display (macroexpand-1 '(my-if (= 1 1) 'yes 'no)))
(newline)
(display (my-if (= 1 2) 'yes 'no))
(newline)
(define-macro (swap! x y) `(let ((tmp ,x)) (set! ,x ,y) (set! ,y tmp)))
(define p 1)
(define q 2)
(swap! p q)
(display (list p q))
(newline)
#+END_SRC

#+RESULTS:
: (cond ((= 1 1) (quote yes)) (else (quote no)))
: no
: (2 1)
