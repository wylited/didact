#+TITLE: SQL, Row by Row
#+SUBTITLE: Watch table scans, nested-loop joins, grouping, sorting, and NULL logic run one row at a time

SQL lets you write what you want (=WHERE age >= 30=) instead of writing a loop, but the database still runs a loop under the covers. This page runs a small TypeScript SQL engine (=CREATE TABLE=, =INSERT=, =SELECT= over =INTEGER= and =TEXT=) where every Step is literally one row operation.

* Scans, filters, and projections

Step through the query below with the *Plan* panel open. Each operator shows *seen / passed / emitted* counters: =Scan users= reads all 5 rows (=5/5/5=), =Filter age >= 30= keeps 2 (=5/2/2=), and =Project= outputs 2 (=2/2/2=). Notice =eve= is left out because her age is =NULL=, and =NULL >= 30= is unknown, not true.

#+NAME: select-where
#+BEGIN_SRC sql
CREATE TABLE users (id INTEGER, name TEXT, city TEXT, age INTEGER);
INSERT INTO users VALUES (1, 'alice', 'HK', 34), (2, 'Bob', 'HK', 27), (3, 'carol', 'SF', 41), (4, 'dave', 'SF', 19), (5, 'eve', 'NY', NULL);
SELECT name, age FROM users WHERE age >= 30;
#+END_SRC

#+RESULTS:
: INSERT 0 5
: 
:  name  | age 
: -------+-----
:  alice | 34  
:  carol | 41  

* Nested-loop joins

This engine joins tables with a plain nested loop so the cost is visible: for every row from =users=, it scans every row of =orders= and tests the =ON= condition. With 3 users and 3 orders, =NestedLoop join orders= checks 9 pairs and emits 2 matches (=9/2/2=). Order 12 (=user_id = 9=) matches nobody and gets dropped. When both tables have an =id= column, qualify it as =users.id= or =orders.id= (bare =id= fails as ambiguous).

#+NAME: nested-loop-join
#+BEGIN_SRC sql
CREATE TABLE users (id INTEGER, name TEXT);
INSERT INTO users VALUES (1, 'alice'), (2, 'Bob'), (3, 'carol');
CREATE TABLE orders (id INTEGER, user_id INTEGER, total INTEGER);
INSERT INTO orders VALUES (10, 1, 100), (11, 3, 60), (12, 9, 999);
SELECT users.name, orders.total FROM users JOIN orders ON users.id = orders.user_id;
#+END_SRC

#+RESULTS:
: INSERT 0 3
: 
: INSERT 0 3
: 
:  name  | total 
: -------+-------
:  alice | 100   
:  carol | 60    

Because nested loops scale as =N * M= (two 200-row tables take 40,000 probes), runs cap out at 100,000 row operations and stop with a line-numbered error instead of freezing your tab.

* =GROUP BY= and =HAVING=

=GROUP BY city= folds rows into per-city buckets one step at a time while updating =COUNT=, =SUM=, =AVG=, =MIN=, and =MAX=. Watch *Current row* as each row gets folded in. Once folding finishes, =HAVING= filters the finished groups (while =WHERE= filters raw rows before grouping).

#+NAME: group-by
#+BEGIN_SRC sql
CREATE TABLE users (id INTEGER, name TEXT, city TEXT, age INTEGER);
INSERT INTO users VALUES (1, 'alice', 'HK', 34), (2, 'Bob', 'HK', 27), (3, 'carol', 'SF', 41), (4, 'dave', 'SF', 19);
SELECT city, COUNT(*), AVG(age) FROM users GROUP BY city;
SELECT city, COUNT(*) FROM users GROUP BY city HAVING COUNT(*) > 1 AND AVG(age) > 30;
#+END_SRC

#+RESULTS:
: INSERT 0 4
: 
:  city | COUNT(*) | AVG(age) 
: ------+----------+----------
:  HK   | 2        | 30.5     
:  SF   | 2        | 30.0     
: 
:  city | COUNT(*) 
: ------+----------
:  HK   | 2        

Any non-aggregated column in =SELECT= must also be in =GROUP BY=. Otherwise SQL would have to guess which =name= to pick out of a multi-row group. Line 3 below fails before reading a single row (the =INSERT= on line 2 still ran first):

#+NAME: grouping-rule
#+BEGIN_SRC sql
CREATE TABLE users (id INTEGER, name TEXT, city TEXT, age INTEGER);
INSERT INTO users VALUES (1, 'alice', 'HK', 34), (2, 'Bob', 'SF', 27);
SELECT name, COUNT(*) FROM users GROUP BY city;
#+END_SRC

#+RESULTS:
: INSERT 0 2

Wrap =name= in =MIN(name)= or add it to =GROUP BY= to fix it.

* =ORDER BY= and =LIMIT=

Sorting runs a stable merge sort where each comparison is one step. =INTEGER= columns sort numerically, =TEXT= columns sort in ASCII order (uppercase before lowercase), and =NULL=s sort last. =LIMIT 3= stops after emitting three rows.

#+NAME: order-limit
#+BEGIN_SRC sql
CREATE TABLE scores (player TEXT, points INTEGER);
INSERT INTO scores VALUES ('alice', 7), ('Bob', 12), ('carol', 12), ('dave', 3);
SELECT player, points FROM scores ORDER BY points DESC, player LIMIT 3;
#+END_SRC

#+RESULTS:
: INSERT 0 4
: 
:  player | points 
: --------+--------
:  Bob    | 12     
:  carol  | 12     
:  alice  | 7      

* =NULL= and =LIKE=

=NULL= means unknown, not zero or empty string. Comparing =NULL= with =>=, ===, or =!= gives unknown, and =WHERE= drops anything that is not true (even =NOT (age > 25)= drops Bob). Use =IS NULL= or =IS NOT NULL= to match missing values. Aggregates skip =NULL=s (=COUNT(*)= counts rows; =COUNT(age)= counts non-null ages).

The last query uses =LIKE=: =%= matches any run of characters, =_= matches one character, and matching is case-sensitive.

#+NAME: null-and-like
#+BEGIN_SRC sql
CREATE TABLE users (name TEXT, city TEXT, age INTEGER);
INSERT INTO users VALUES ('alice', 'HK', 34), ('Bob', 'HK', NULL), ('carol', 'SF', 28);
SELECT name FROM users WHERE age IS NULL;
SELECT name FROM users WHERE age > 25;
SELECT name FROM users WHERE name LIKE '%o%';
#+END_SRC

:  Bob

:  alice 
:  carol 
:

:  Bob   
:  carol
