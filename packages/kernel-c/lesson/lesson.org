#+TITLE: C in the Browser
#+SUBTITLE: Real clang compiling to WebAssembly right in this tab

Every block on this page is real, editable C compiled by *clang* (LLVM 22 via =@yowasp/clang=, ~105 MB downloaded once on first run and cached by your browser). When you click *Run*, clang compiles your code to =wasm32-wasi=, links it with =wasm-ld=, and runs the resulting WebAssembly module in this tab. Compiler errors point to the exact line in the editor.

Because WebAssembly has no direct OS access, a small WASI shim handles the basics:

- *Supported:* =stdout=/=stderr= (=fd_write=), exit codes (=proc_exit=), browser crypto (=random_get=), and a wall clock (=clock_time_get=).
- *Unsupported:* File I/O, =nanosleep=, and process spawning fail cleanly with an explicit "unsupported WASI call" error instead of silently doing nothing.
- *Isolation:* Each block compiles and runs in its own session. A tight infinite loop with no I/O cannot be interrupted by WebAssembly and will freeze the tab.

Open the right-hand panel after running a block to inspect the compile log, exit code, binary size, compile time, and a hex dump of the first 256 bytes of the linked =.wasm= module.

* Printing with =puts= and =printf=

=puts= prints a string and automatically adds a newline. =printf= gives you format specifiers like =%d= for signed integers, without adding a newline unless you include =\n=.

#+NAME: hello
#+BEGIN_SRC c
#include <stdio.h>

int main(void) {
  puts("Hello, world!");
  printf("2 + 3 = %d\n", 2 + 3);
  return 0;
}
#+END_SRC

#+RESULTS:
: Hello, world!
: 2 + 3 = 5

* Summing with a =for= loop

A standard C =for= loop initializes =i = 1=, checks =i <= 10= before each iteration, and increments =i= afterward. Try changing the upper bound or introducing a syntax error (like dropping a semicolon) to see clang's diagnostics on the exact line.

#+NAME: sum-loop
#+BEGIN_SRC c
#include <stdio.h>

int main(void) {
  int sum = 0;
  for (int i = 1; i <= 10; i++) sum += i;
  printf("%d\n", sum);
  return 0;
}
#+END_SRC

#+RESULTS:
: 55

* Recursion: =factorial(10)=

=factorial= uses a ternary expression to stop at =n <= 1= and otherwise multiply =n= by =factorial(n - 1)=. Using =long= (and =%ld= in =printf=) gives room for larger products, though =factorial(13)= will still overflow a 32-bit =long= on =wasm32=. Try bumping =10= up to see where overflow kicks in.

#+NAME: factorial
#+BEGIN_SRC c
#include <stdio.h>

long factorial(int n) {
  return n <= 1 ? 1L : n * factorial(n - 1);
}

int main(void) {
  printf("%ld\n", factorial(10));
  return 0;
}
#+END_SRC

#+RESULTS:
: 3628800
