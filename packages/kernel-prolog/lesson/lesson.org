#+TITLE: Prolog: State the Facts, Watch It Search
#+SUBTITLE: Unification, SLD resolution, backtracking, and cut on a steppable Prolog engine

* Facts, variables, and queries

A Prolog program is a set of logical facts and rules rather than step-by-step instructions. A fact like =likes(ada, prolog).= states a relationship. A query like =?- likes(ada, X).= asks Prolog to find a value for the capitalized variable =X= that makes the statement true.

Run the block below and check the *Bindings* panel: Prolog finds the first match (=X = prolog=) and stops. Running again backtracks to find the next answer (=X = lisp=), and eventually prints =No.= when no matches remain. The unifier also enforces the *occurs check*, so cyclic terms like =?- X = f(X).= fail cleanly instead of hanging.

#+NAME: facts-and-queries
#+BEGIN_SRC prolog
likes(ada, prolog).
likes(ada, lisp).
likes(bob, prolog).
?- likes(ada, X).
#+END_SRC

#+RESULTS:
: Yes.
: X = prolog

* Rules and the Goal stack

A rule uses =:-= ("if") to define a relationship in terms of others:

=grandparent(X, Z) :- parent(X, Y), parent(Y, Z).=

Single-step the block below and watch the *Goal stack* panel. Prolog always works on the leftmost goal first: it replaces =grandparent(tom, G)= with the two subgoals =parent(tom, Y)= and =parent(Y, G)=, unifies =Y = mary=, and then proves =parent(mary, ann)=. When the goal stack empties, you have a solution.

#+NAME: rules-and-conjunction
#+BEGIN_SRC prolog
parent(tom, mary).
parent(mary, ann).
parent(mary, pat).
grandparent(X, Z) :- parent(X, Y), parent(Y, Z).
?- grandparent(tom, G).
#+END_SRC

#+RESULTS:
: Yes.
: G = ann

* Recursion and collecting all answers with =findall=

=member/2= is not built in here, so we write it in two clauses: =E= is in a list if it matches the head =[E|_]= (where =_= is a throwaway wildcard), or if it is a member of the tail =T=.

To collect *every* solution at once instead of stopping at the first, use =findall(Template, Goal, ResultList)=. Below, =findall= runs =member(E, [ada, bob, cy])= to exhaustion and binds =Es= to all matches in clause order. (=E = E= just means the query variable =E= stays unbound outside =findall=.)

#+NAME: member-by-recursion
#+BEGIN_SRC prolog
member(E, [E|_]).
member(E, [_|T]) :- member(E, T).
?- findall(E, member(E, [ada, bob, cy]), Es).
#+END_SRC

#+RESULTS:
: Yes.
: E = E
: Es = [ada, bob, cy]

* Backtracking: running =append= in reverse

Because Prolog predicates are relations, not one-way functions, =append/3= works both forward (joining two lists) and backward (splitting one list into every possible prefix/suffix pair).

Step through the query below with the *Choice points* panel open: each recursive call pushes a saved decision point onto the stack, and backtracking pops them one by one to generate all three splits of =[1, 2]=.

#+NAME: append-generates
#+BEGIN_SRC prolog
append([], Ys, Ys).
append([X|Xs], Ys, [X|Zs]) :- append(Xs, Ys, Zs).
?- findall(p(Xs, Ys), append(Xs, Ys, [1, 2]), Ps).
#+END_SRC

#+RESULTS:
: Yes.
: Xs = Xs
: Ys = Ys
: Ps = [p([], [1, 2]), p([1], [2]), p([1, 2], [])]

* Cut (=!=): pruning unnecessary backtracking

The *cut* operator (=!=) always succeeds and discards all pending choice points created since the current predicate was entered — committing Prolog to the clause it already chose.

Compare =max3= (with cut) and =maxu= (without cut) below:

- =max3(5, 3, M)= matches the first clause, hits =!=, and commits — returning only =[5]=.
- =maxu(5, 3, M)= finds =5=, then backtracks into the second clause and also returns =3=, producing =[5, 3]=.

#+NAME: cut-prunes
#+BEGIN_SRC prolog
max3(X, Y, X) :- X >= Y, !.
max3(_, Y, Y).
maxu(X, Y, X) :- X >= Y.
maxu(_, Y, Y).
?- findall(M, max3(5, 3, M), WithCut).
?- findall(M, maxu(5, 3, M), WithoutCut).
#+END_SRC

#+RESULTS:
: Yes.
: M = M
: WithCut = [5]
: Yes.
: M = M
: WithoutCut = [5, 3]
