#+TITLE: Regular Expressions, Without Backtracking
#+SUBTITLE: Compile patterns to a Thompson NFA and simulate every active state in parallel — guaranteed linear time

* Block format and how the engine works

Each block starts with a regex between slashes (=/a(b|c)+d/=, no flags), followed by one test input per line. Lines starting with =#= are comments, and input lines interpret six escapes (=\n=, =\t=, =\r=, =\f=, =\v=, =\\=).

Instead of backtracking like JavaScript or Python's =re=, this kernel compiles the pattern into a *Thompson NFA* and advances a *set* of all active states together, one character per step:

- *The machine* panel shows the compiled NFA graph.
- *NFA states* highlights every state currently active (and marks newly entered states).
- *Input* shows the current start offset and scan position.

Basic syntax: literals match themselves, =.= matches any character except =\n=, character classes like =[a-z]= and =[^0-9]= match listed/ranged characters (no escapes inside classes), and =^=/=$= anchor to the start and end of the whole string (no multiline mode).

#+NAME: regex-classes
#+BEGIN_SRC regex
# leftmost start, longest span — watch the Input panel
/[abc]+/
zzabcaz
zzz
#+END_SRC

#+RESULTS:
: match [2,6)
: no match

For unanchored patterns, the engine tries start offsets =0, 1, 2, ...= until one matches, and keeps the *longest* match from that earliest start (POSIX leftmost-longest semantics).

#+NAME: regex-anchors
#+BEGIN_SRC regex
/^b.*d$/
bcd
bcdex
xbcd
#+END_SRC

#+RESULTS:
: match [0,3)
: no match
: no match

Because =.= does not match newlines, =a\nb= fails =/a.b/= while =axb= matches:

#+NAME: regex-dot
#+BEGIN_SRC regex
/a.b/
a\nb
axb
#+END_SRC

#+RESULTS:
: no match
: match [0,3)

* Alternation and quantifiers: leftmost-longest

In backtracking engines like JS or Python, =/a|ab/= stops at the first matching branch (="a"=). A Thompson NFA tracks *both* branches at once and picks the longest match, so =/a|ab/= and =/ab|a/= return the exact same span.

#+NAME: regex-alt
#+BEGIN_SRC regex
/ab|a/
ab
a
xab
#+END_SRC

#+RESULTS:
: match [0,2)
: match [0,1)
: match [1,3)

Supported quantifiers are =*= (0+), =+= (1+), =?= (0 or 1), and counted ranges ={n}=, ={n,}=, ={n,m}=. Counted quantifiers expand into repeated NFA states (=a{2,3}= becomes =a a a?=), visible in *The machine* panel. Escape literal braces as =\{=.

#+NAME: regex-quant
#+BEGIN_SRC regex
/a{2,3}/
aaaa
aa
a
#+END_SRC

#+RESULTS:
: match [0,3)
: match [0,2)
: no match

Optional characters use =?=:

#+NAME: regex-optional
#+BEGIN_SRC regex
/colou?r/
color
colour
colr
#+END_SRC

#+RESULTS:
: match [0,5)
: match [0,6)
: no match

* Capturing groups

Parentheses =(...)= capture half-open =[start, end)= spans numbered by opening parenthesis; =(?:...)= groups without capturing. When a group repeats (like =(ab)+=), it reports the final iteration's span — matching standard regex behavior without backtracking.

#+NAME: regex-groups
#+BEGIN_SRC regex
/(a(b))c/
xabc
#+END_SRC

#+RESULTS:
: match [1,4) groups: 1=[1,3) 2=[2,3)

#+NAME: regex-iterate
#+BEGIN_SRC regex
/(ab)+/
abab
ab
#+END_SRC

#+RESULTS:
: match [0,4) groups: 1=[2,4)
: match [0,2) groups: 1=[0,2)

Step through =regex-groups= with the *Captures* panel open to see the zero-width open and close marker states fire as characters are consumed.

* Shorthand classes: =\d=, =\w=, =\s=

This engine uses strict ASCII definitions (and uppercase =\D=, =\W=, =\S= for their complements):

- =\d= is =[0-9]=
- =\w= is =[A-Za-z0-9_]=
- =\s= is =[ \t\r\n\f\v]=

Note: shorthands cannot be placed inside =[...]= classes in this subset.

#+NAME: regex-words
#+BEGIN_SRC regex
/\w+ \d+/
room 404
room 4o4
#+END_SRC

#+RESULTS:
: match [0,8)
: match [0,6)

#+NAME: regex-space
#+BEGIN_SRC regex
/\s[a-z]+/
hi there
hi\tthere
#+END_SRC

#+RESULTS:
: match [2,8)
: match [2,8)

* Features intentionally rejected (and why)

Everything outside pure regular languages or one-pass NFA simulation fails at load time with a line-numbered error:

- *Backreferences (=\1=, =\k<name>=):* Matching an arbitrary repeated string (=ww=) is provably non-regular — a finite-state machine has no unbounded memory to store earlier substrings.
- *Lookaround (=(?=...)=, =(?<=...)=):* Excluded to keep simulation strictly single-pass left-to-right.
- *Lazy quantifiers (=*?=, =+?=):* Not applicable under POSIX leftmost-longest matching.
- *Named groups, Unicode properties (=\p{L}=), and word boundaries (=\b=):* Use numbered groups, ASCII classes, and explicit anchors instead.

Syntax mistakes (dangling =*=, unclosed =(= or =[=, invalid ={2,1}=, empty =[]=, reversed =[z-a]=) also report their exact line.

* Why =/(a*)*/= never blows up here

On a backtracking engine, nested quantifiers like =/(a*)*/= against 1,000 =a=s followed by =b= explode into exponential O(2^n) backtracking paths (ReDoS). A Thompson NFA deduplicates active states at every character, so it never visits more states per character than exist in the compiled graph.

#+NAME: regex-linear
#+BEGIN_SRC regex
/(a*)*/
aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaab
#+END_SRC

#+RESULTS:
: match [0,1000) groups: 1=[0,1000)

All 1,001 characters finish in 1,001 steps: one per =a=, plus one step where =b= drops every live state. Safety caps (4,096 NFA states max, 100,000 character steps, 5,000,000 state visits) ensure pathological patterns fail fast with a clean error instead of hanging your browser.
