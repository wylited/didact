#+TITLE: RISC-V (RV32IM), Stepped Live
#+SUBTITLE: 32-bit fixed-width instructions, ABI registers, and ecall on a steppable simulator

* Registers and branches

RV32IM has 32 registers (=x0=–=x31=) and every instruction is 4 bytes wide. Register =x0= (=zero=) is hardwired to =0=, so writes to it do nothing.

| Register      | ABI name | Role                      |
|---------------+----------+---------------------------|
| x0            | zero     | always 0                  |
| x1            | ra       | return address            |
| x2            | sp       | stack pointer             |
| x10–x17       | a0–a7    | arguments, ecall services |
| x5–x7, x28–31 | t0–t6    | caller-saved temporaries  |
| x8–x9, x18–27 | s0–s11   | callee-saved              |

There is no flags register. Branches like =blt= and =bne= compare two registers and jump in a single instruction. Look at *Branch context* in the right-hand panel to see the last comparison and whether it was taken.

* =ecall= services

Put the service number in =a7=, put any argument in =a0=, and run =ecall=:

| =a7= | Service      | Effect                             |
|------+--------------+------------------------------------|
| 1    | print int    | print =a0= as a signed decimal     |
| 4    | print string | print NUL-terminated bytes at =a0= |
| 11   | print char   | print the low byte of =a0=         |
| 10   | exit         | stop execution                     |
| 93   | exit         | same as 10 (Linux convention)      |

* Hello, RISC-V

=la= loads the address of =msg= into =a0= and =li= puts service =4= in =a7=. Edit the string in =.asciz= and hit Run.

#+NAME: hello
#+BEGIN_SRC riscv
        .text
hello:
        la      a0, msg        # a0 -> address of the string
        li      a7, 4          # service 4: print string
        ecall
        li      a0, 10         # '\n'
        li      a7, 11         # service 11: print char
        ecall
        li      a0, 0          # exit code 0
        li      a7, 10         # service 10: exit
        ecall

        .data
msg:
        .asciz "Hello, RISC-V!"
#+END_SRC

#+RESULTS:
: Hello, RISC-V!

* Summing 1 through 10

=t0= counts from =1= up to =10= while =t2= holds the running sum. Once =10 < t0=, =blt t1, t0, done= jumps out of the loop and prints =55=. Step a few times to watch =t0= and =t2= highlight as they update.

#+NAME: sum-loop
#+BEGIN_SRC riscv
        .text
        li      t0, 1          # i = 1
        li      t1, 10         # limit = 10
        li      t2, 0          # sum = 0
loop:
        add     t2, t2, t0     # sum += i
        addi    t0, t0, 1      # i++
        blt     t1, t0, done   # if 10 < i, leave the loop
        j       loop
done:
        mv      a0, t2         # a0 = 55
        li      a7, 1          # service 1: print int
        ecall
        li      a0, 10         # newline
        li      a7, 11
        ecall
        li      a0, 0
        li      a7, 10         # exit
        ecall
#+END_SRC

#+RESULTS:
: 55

* Signed vs unsigned byte loads (=lb= vs =lbu=)

When you load a single byte (=0xFF=) into a 32-bit register, =lb= sign-extends the top bit (=0xFFFFFFFF = -1=) while =lbu= zero-extends it (=0x000000FF = 255=). After running, check the =.data= hex view to see the four =FF= bytes written by =sw=.

#+NAME: bytes
#+BEGIN_SRC riscv
        .text
        li      t0, -1         # 0xFFFFFFFF
        la      t1, buf        # t1 -> scratch word in .data
        sw      t0, 0(t1)      # store the word: FF FF FF FF
        lb      a0, 0(t1)      # sign-extend byte FF -> -1
        li      a7, 1          # print int
        ecall
        li      a0, 32         # ' '
        li      a7, 11         # print char
        ecall
        lbu     a0, 0(t1)      # zero-extend byte FF -> 255
        li      a7, 1
        ecall
        li      a0, 10         # newline
        li      a7, 11
        ecall
        li      a0, 0
        li      a7, 10         # exit
        ecall

        .data
buf:
        .word 0
#+END_SRC

#+RESULTS:
: -1 255

Try setting a breakpoint on =add t2, t2, t0= (execution pauses before the instruction runs), or introducing a typo like =addd= to see the line-mapped assembler error.
