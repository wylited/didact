* Tables do everything

Lua has only one compound data structure: the *table*. A table is a hash map that also acts as an array when you use consecutive integer keys starting at 1. You can even mix both in the same table: ={10, 20, 30, name = "xs"}= stores =10, 20, 30= under keys =1, 2, 3= and ="xs"= under key ="name"=.

Run the block below and watch the *Tables* panel. Array entries (=t[1]=, =t[2]=, ...) appear first, followed by hash entries, with =Δ= marking rows changed by the last step. The length operator =#= counts consecutive integer keys starting from 1 (and ignores hash keys). Note: this teaching kernel never garbage-collects tables, so the panel keeps a full history of allocations.

#+NAME: tables-101
#+BEGIN_SRC lua
local t = {10, 20, 30, name = "xs"}
t[4] = 40
t.lang = "lua"
print(#t, t[1], t.name, t.lang)
#+END_SRC

#+RESULTS:
: 4	10	xs	lua

Two iterators match the two parts of a table:

- =ipairs(t)= walks integer keys =1, 2, 3, ...= and stops at the first =nil= gap (matching =#t=).
- =pairs(t)= walks *every* key in the table — array entries first, then hash keys.

#+NAME: tables-pairs
#+BEGIN_SRC lua
local t = {10, 20, name = "xs"}
for i, v in ipairs(t) do print(i, v) end
for k, v in pairs(t) do print(k, v) end
#+END_SRC

#+RESULTS:
: 1	10
: 2	20
: 1	10
: 2	20
: name	xs

* Multiple returns and parallel assignment

Lua functions can return multiple values without wrapping them in a tuple or array. The rule for how they expand is simple:

- A call expands to all its return values only when it is the *last* expression in a list (such as =local lo, hi = minmax(xs)=).
- Extra values are silently dropped if there are fewer targets (=local only = minmax(xs)=).
- Wrapping a call in parentheses =(minmax(xs))= forces it to a single value.

Because Lua evaluates the entire right-hand side before assigning the left-hand side, swapping two variables is just =a, b = b, a=.

#+NAME: multiple-returns
#+BEGIN_SRC lua
local function minmax(t)
  local lo, hi = t[1], t[1]
  for i = 2, #t do
    if t[i] < lo then lo = t[i] end
    if t[i] > hi then hi = t[i] end
  end
  return lo, hi
end
local xs = {3, 1, 4, 1, 5}
local lo, hi = minmax(xs)
local only = minmax(xs)
print(lo, hi, only, (minmax(xs)))
a, b = 1, 2
a, b = b, a
print(a, b)
#+END_SRC

#+RESULTS:
: 1	5	1	1
: 2	1

* Two defaults that trip up Python and C devs

Two Lua rules catch almost everyone at first:

- *Only =nil= and =false= are falsy.* Both =0= and =""= are truthy!
- *Arrays are 1-indexed.* =t[1]= is the first element, =t[0]= is =nil= unless you explicitly set it, and =#t= counts starting at 1.

#+NAME: truth-and-one
#+BEGIN_SRC lua
if 0 then print("0 is truthy") end
if "" then print("the empty string is truthy") end
if nil or false then print("never") else print("only nil and false are falsy") end
local t = {"a", "b", "c"}
print(t[1], t[0], #t)
#+END_SRC

#+RESULTS:
: 0 is truthy
: the empty string is truthy
: only nil and false are falsy
: a	nil	3

* Integers vs floats

Lua 5.4 distinguishes integers (=1=) from floats (=1.0=):

- =/= always returns a float (=7 / 2= is =3.5=).
- =//= is floor division (toward negative infinity, like Python): =-7 // 2= is =-4=, not =-3=. It returns an integer when both operands are integers.
- =%= follows the sign of the divisor (=5 % -3= is =-1=).
- Equal numeric values compare equal across subtypes: =1 == 1.0= is =true=.

Note: real Lua uses 64-bit integers, whereas this browser kernel stores numbers as JavaScript doubles and rejects integer literals past =2^53= at load time instead of silently losing precision.

#+NAME: ints-and-floats
#+BEGIN_SRC lua
print(1, 1.0, 7 / 2)
print(7 // 2, 7.0 // 2, -7 // 2)
print(5 % 3, 5 % -3, -5 % 3)
print(1 == 1.0)
#+END_SRC

#+RESULTS:
: 1	1.0	3.5
: 3	3.0	-4
: 2	-1	1
: true

* Metatables: how Lua builds inheritance

Lua has no =class= keyword. Instead, any table can have a *metatable* with an =__index= fallback that runs whenever a key lookup misses:

- If =__index= is another table, Lua keeps looking up the key there (and chains through *its* metatable too).
- If =__index= is a function, Lua calls =fn(table, key)= and returns the result.

The colon syntax is just shorthand for passing =self=: =rex:greet()= calls =rex.greet(rex)=, and =function Animal:greet()= automatically declares =self= as the first parameter.

#+NAME: metatables
#+BEGIN_SRC lua
local Animal = {}
function Animal:greet() return self.sound .. "!" end
local Dog = {}
Animal.__index = Animal
setmetatable(Dog, {__index = Animal})
local Dog2 = {}
Dog.__index = Dog
setmetatable(Dog2, {__index = Dog})
local rex = {sound = "woof"}
setmetatable(rex, {__index = Dog2})   -- two levels up to Animal
local fallback = setmetatable({}, {__index = function(t, k) return k .. "?" end})
print(rex:greet())
print(fallback.anything)
#+END_SRC

#+RESULTS:
: woof!
: anything?
